# 一、路线定位与最终目标

这条路线面向已经接触过 Java 后端开发、会一些基础 SQL，但 SQL
知识不够系统、部分内容已经遗忘，并且希望逐步掌握数据库原理和工程实践的学习者。

路线从基础查询重新建立知识结构，再逐步进入数据库设计、索引、事务、InnoDB
和 Java 工程实践。它不是单纯的 SQL 语法教程，也不是 DBA
培训或数据库内核研究路线。

## 最终能力目标

完成路线后，目标是能够：

-   **熟练使用 SQL：**
    独立编写常见及复杂业务查询，理解查询逻辑和边界情况。
-   **设计数据库：**
    根据业务需求设计表结构、字段类型、主键、约束和表关系。
-   **设计索引：** 根据查询场景设计合理索引，理解收益、成本和限制。
-   **优化 SQL：**
    使用执行计划分析查询，定位常见性能问题并提出优化方案。
-   **理解事务：**
    理解隔离级别、MVCC、锁和常见并发问题，并能通过实验验证。
-   **理解 InnoDB：** 掌握索引、数据页、Buffer Pool、Redo Log、Undo
    Log、Binlog 等关键机制。
-   **完成 Java 集成：** 理解 JDBC、MyBatis、连接池和 Spring
    事务，能够排查常见数据库访问问题。
-   **处理常见生产问题：** 对慢
    SQL、锁等待、死锁、DDL、备份恢复和复制等问题具备初步判断与排查能力。

**我们的目标是成为懂数据库原理、能设计数据模型、能优化
SQL、能解决数据库工程问题的 Java 后端工程师。**

## 不以什么为目标

-   不以成为专职 MySQL DBA 为目标。
-   不以研究或修改 MySQL 内核源码为目标。
-   不要求掌握所有数据库产品。
-   不把背诵大量面试题当作主线。
-   不在没有业务需要时研究复杂集群运维。

# 二、学习原则与推进方式

## 一个 Node 的标准结构

每个 Node 尽量按照以下方式学习：

1.  **学习目标：** 学完应该理解什么、能够做什么。
2.  **核心知识：** 概念、使用场景、工作机制、边界条件和前后联系。
3.  **实践任务：** 亲自编写 SQL、创建表、准备数据、修改配置或编写 Java
    代码。
4.  **实验验证：**
    对索引、事务、锁和执行计划等内容，尽量通过实验观察实际结果。
5.  **完成标准：** 能够独立解释原理、完成实践，并判断适用场景。

简单 Node 可以较快完成；复杂 Node 可以分几次学习。每个 Node
不要求篇幅相同，也不按自然日计算。

## 推进规则

-   按 Node 推进，不按自然日推进。
-   不为了赶进度跳过前置知识。
-   先理解再记忆，不追求背诵定义。
-   理论与实践结合，重要知识点尽量配有 SQL 或 Java 实验。
-   定期回顾，并主动联系之前学过的内容。
-   允许回退；如果后续实验暴露基础问题，可以回到之前的 Node。
-   看过资料不等于完成；能够解释、实践和迁移应用才算掌握。
-   文档和实验服务于学习，不为了维护仓库而维护仓库。

## 建议学习节奏

每个 Node 可以采用以下流程：

1.  先理解概念和问题背景。
2.  学习必要的原理。
3.  自己编写 SQL 或代码。
4.  运行实验并观察结果。
5.  用自己的话解释结论。
6.  更新 `progress.md`。

复杂 Node（例如联合索引、MVCC、Next-Key
Lock）可能需要多轮讲解和实验。不要因为一个 Node 学了几天就认为进度太慢。

# 三、环境与技术基线

## 版本基线

-   主线以 **MySQL 8.4 LTS** 作为学习和实验基线。
-   如果工作项目使用 MySQL
    8.0，应注意小版本和功能差异，不把某个版本的行为无条件推广到所有版本。
-   学习时记录 MySQL 版本、存储引擎、隔离级别和 SQL Mode。
-   主要使用 InnoDB。除非某个 Node 明确比较存储引擎，否则不把 MyISAM
    作为实践主线。

## 建议工具

-   MySQL Server：本地安装或使用 Docker 运行。
-   SQL 客户端：DBeaver、MySQL Workbench 或命令行客户端，任选其一。
-   Java 开发环境：进入 Phase 7 后使用。
-   Git：保存实验 SQL、实验记录和项目代码。
-   Docker Compose：可选，用于快速创建和重置实验环境。

不要求一开始安装很多工具。先保证能够连接 MySQL、创建数据库、执行 SQL
和查看结果。

## 实验安全规则

-   实验使用独立数据库和测试数据，不直接在工作数据库执行未知语句。
-   执行 UPDATE、DELETE、ALTER、DROP 前，确认目标库、目标表和影响范围。
-   学习事务和锁时，使用多个独立连接模拟并发。
-   记录实验版本、SQL、执行结果和结论。
-   不在真实生产环境随意运行压力测试、锁实验或 DDL 实验。

## 练习原则

1.  先学习对应知识，再做相关题目，不建议完全零基础时直接盲刷。
2.  优先使用 MySQL 方言，注意题目环境和本地 MySQL 版本可能存在差异。
3.  先独立思考和编写，再查看提示或题解。
4.  做完后解释 SQL 的执行逻辑、JOIN 关系和聚合粒度。
5.  对做错或看题解才完成的题目，记录错误原因并隔一段时间重做。
6.  不以刷题速度为目标，重点是能否独立推导和解释。

  ------------------------------------------------------------------------------------
  路线阶段                            练习安排
  ----------------------------------- ------------------------------------------------
  Phase 0                             暂不刷题，先建立环境和数据库概念

  Phase 1                             学完 SELECT、过滤、排序和聚合后，开始 SQL 50
                                      对应基础题

  Phase 2                             学习 JOIN、子查询、CTE、窗口函数时完成对应题目

  Phase 3                             将题目涉及的表结构和约束作为数据库设计讨论素材

  Phase 4 及以后                      不以 LeetCode
                                      为主要练习，转向执行计划、索引、事务和工程实验
  ------------------------------------------------------------------------------------

SQL 50
的具体题目分配可以在学习过程中按知识点调整，不要求机械地按照题号顺序刷完。

## 进度记录规则

每完成一个 Node，更新 `progress.md`：

-   当前 Phase。
-   当前 Node。
-   已完成 Node。
-   正在学习的 Node。
-   遇到的问题。
-   下一步任务。
-   必要的实验或代码链接。

进度记录必须反映真实情况，不因为路线文档已经写好就提前标记完成。

## 路线调整规则

-   只有发现前置依赖缺失、内容重复或实践目标不合理时，才调整 Node。
-   新增内容优先作为现有 Node 的补充，不轻易扩大路线规模。
-   确实需要新增 Node 时，说明新增原因和前后依赖。
-   不因为某项新技术热门就随意加入。
-   不把 Redis、其他数据库或 Agent 内容混入本路线。
-   学习过程中可以根据实际工作问题调整讲解顺序，但应保留整体知识结构。

## 与 Agent 学习路线的关系

MySQL 是独立的数据库基础能力路线，与仓库中的 Agent 路线并行：

-   Agent 路线继续按照 Agent 目录中的既定规划推进。
-   MySQL 路线负责补齐 SQL、数据库设计、索引、事务和 Java
    数据库工程能力。
-   两条路线互相支持，但不要求同时推进，也不互相等待。
-   当 Agent
    项目需要会话持久化、任务状态、工具执行记录或业务数据存储时，可以把
    MySQL 知识应用进去。

**不需要等 MySQL 学完才继续 Agent，也不需要为了 Agent 暂停 MySQL
的基础学习。**

## 最后的学习约定

这条路线的价值不在于完成 136 个编号，而在于真正建立数据库工程能力。

我们不追求最快速度，不追求一次学会，也不追求把所有数据库技术都学一遍。

每次只解决眼前一个 Node 的问题：

-   理解它是什么。
-   理解它为什么存在。
-   理解它如何工作。
-   亲手实践并验证。
-   能够解释并应用。

**路线可以很长，但每次只走好当前这一步。**

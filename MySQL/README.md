# MySQL Engineer 学习实验室

> 通过系统学习、SQL 练习和真实实验，逐步建立扎实的 MySQL
> 与数据库工程能力。

这里记录 MySQL 学习过程中的路线、笔记、SQL
练习、实验和项目。目标不是把这里整理成一本完美的教材，而是通过持续实践，真正理解数据库并能在
Java 后端项目中正确使用它。

------------------------------------------------------------------------

## 一、学习目标

本路线面向有一定 Java 开发经验、但 SQL
基础不够扎实，希望系统补齐数据库知识的学习者。

最终希望具备以下能力：

-   **SQL 查询：** 能独立编写常见及复杂业务查询，理解 SQL 的执行逻辑。
-   **数据库设计：**
    能根据业务需求设计表结构、字段、主键、唯一约束和索引。
-   **性能优化：** 能阅读执行计划，分析慢 SQL，并提出合理的优化方案。
-   **事务与并发：** 理解事务隔离、MVCC、锁和常见并发问题。
-   **底层原理：** 理解 InnoDB 的关键机制，而不是只记忆概念。
-   **Java 工程实践：** 能处理 Java
    应用中的连接池、事务管理、批量操作和数据库访问问题。
-   **生产问题排查：**
    对慢查询、锁等待、死锁、DDL、备份恢复和主从复制等问题具备初步分析能力。

本路线的目标是培养具备数据库工程能力的 Java 后端开发者，而不是培养 MySQL
DBA 或数据库内核开发者。

------------------------------------------------------------------------

## 二、学习方式

采用三种方式相互配合，而不是只看教程或只刷题。

### 1. 系统学习：按照 Node 推进

以 `MySQL Engineer 循序渐进学习路线.md` 为主线。每个 Node
聚焦一个明确的知识点，逐步建立知识之间的联系。

每个 Node 尽量包含：

1.  **学习目标：** 学完应该理解什么、能够做什么。
2.  **核心原理：** 理解它为什么这样工作，而不只是记住结论。
3.  **实践任务：** 亲自编写 SQL、代码或配置。
4.  **实验验证：** 通过数据、执行计划或并发实验观察结果。
5.  **完成标准：** 能够独立解释并在合适的场景中应用。

一个 Node 可以学习多次、花费多天。不要为了赶进度而跳过没有理解的内容。

### 2. SQL 练习：使用 LeetCode

优先使用 LeetCode 的 **SQL 50** 作为 SQL 查询训练材料。

-   在学习基础查询、JOIN、聚合、子查询和窗口函数时，安排对应题目。
-   尽量使用 MySQL 方言完成练习。
-   不以刷题数量作为目标，重点是理解需求、推导查询并解释自己的写法。
-   SQL 题目主要训练查询能力，不能代替索引、事务、InnoDB
    和生产工程实践。

官方练习入口：

-   [LeetCode SQL 50](https://leetcode.com/studyplan/top-sql-50/)
-   [力扣 SQL 50](https://leetcode.cn/studyplan/top-sql-50/)

### 3. MySQL 实验：验证数据库行为

对重要知识点亲自搭建表、准备数据并进行实验。例如：

-   比较有无索引时的执行计划。
-   观察联合索引在不同查询条件下的使用情况。
-   使用 `EXPLAIN` 分析 SQL。
-   模拟多个事务同时读取和修改数据。
-   观察锁等待、死锁和事务隔离现象。
-   对比不同分页方案和批量操作方式。

**原则：能通过实验观察的知识，尽量不要只靠背诵。**

## 三、学习阶段

以下是整体阶段规划。详细
Node、前后依赖和完成标准以正式学习路线文件为准。

  -------------------------------------------------------------------------------------------
  阶段                    学习主题                核心目标
  ----------------------- ----------------------- -------------------------------------------
  Phase 0                 数据库基础认知          建立数据库、MySQL、存储引擎等基础概念

  Phase 1                 SQL 基础                熟练掌握查询、过滤、排序、聚合和 JOIN

  Phase 2                 进阶 SQL                掌握子查询、CTE、窗口函数和复杂业务查询

  Phase 3                 数据库设计              能设计合理的表结构、约束和关系

  Phase 4                 索引与 SQL 性能优化     理解索引结构，能分析和优化查询

  Phase 5                 事务与并发控制          理解 ACID、隔离级别、MVCC 和锁

  Phase 6                 InnoDB 底层原理         理解日志、缓存、数据页和崩溃恢复等机制

  Phase 7                 Java 后端数据库工程实践 掌握 JDBC、MyBatis、连接池和 Spring 事务

  Phase 8                 生产环境与架构          了解监控、排障、DDL、备份恢复、复制和扩展
  -------------------------------------------------------------------------------------------

学习顺序从基础到工程实践逐步推进。具体内容可以根据实际掌握情况调整，但不随意跳过关键前置知识。

## 四、贯穿学习的业务场景

尽量使用真实业务，而不是始终使用 `student`、`teacher`、`score`
等教学表。

可以逐步构建一个广告投放系统的数据模型，例如：

-   `account`：广告账户
-   `campaign`：广告计划
-   `adset`：广告组
-   `ad_report`：广告报表
-   `operation_record`：操作记录

在不同阶段持续使用这组业务数据：

-   学 SQL：查询账户、计划、报表和关联数据。
-   学数据库设计：设计主键、唯一约束、字段类型和表关系。
-   学索引：分析常见业务查询并设计索引。
-   学事务：模拟预算修改、状态变更和幂等操作。
-   学锁：模拟多个请求同时修改同一条业务记录。
-   学 Java 集成：通过 Java 服务访问数据库。

最终可以把所学内容应用到 Agent 项目及 AdsPilot 等综合项目中。

## 六、学习原则

1.  **先理解，再记忆。** 不追求背诵大量面试八股。
2.  **先掌握基础，再深入底层。** 不在 SQL 基础不牢时急着研究复杂的
    InnoDB 机制。
3.  **理论必须配合实践。** 尽量通过 SQL、执行计划和实验验证结论。
4.  **重视业务场景。**
    学会判断某种设计在什么情况下合适，而不是只记住固定答案。
5.  **不追求无意义的刷题量。** LeetCode
    用来训练和检验，不是学习路线本身。
6.  **不以 DBA 为目标。** 重点放在 Java 后端开发真正需要的数据库能力。
7.  **允许反复学习。** 忘记很正常，重要的是能够重新理解并建立联系。
8.  **记录进度，但不被进度绑架。**
    仓库服务于学习，而不是为了维护仓库而学习。

## 七、与 Agent 学习路线的关系

MySQL 是独立的基础能力学习主线，与仓库中的 `Agent/` 学习路线并行。

两条路线不需要每天同时推进，也不要求互相等待：

-   Agent 路线重点学习 LLM 应用、Tool Calling、Agent
    Loop、RAG、Memory、Workflow 和生产级 Agent 工程。
-   MySQL 路线重点补齐 SQL、数据建模、索引、事务、InnoDB 和 Java
    数据库工程实践。

当 Agent 项目需要持久化会话、工具执行记录、任务状态或业务数据时，可以把
MySQL 中学到的知识应用进去。

**Agent 学习路线仍然按照 Agent 目录中的既定规划推进；MySQL
路线不会擅自替代或改变它。**

------------------------------------------------------------------------

## 八、开始学习

正式开始时，先从路线中的第一个 Node 开始。每完成一个 Node，再更新
`progress.md`，明确下一步学习内容。

不必一次学完所有内容，也不必一开始就把所有笔记整理得很完整。

**先去理解，先去实践，先去验证。让知识真正成为自己的能力。**

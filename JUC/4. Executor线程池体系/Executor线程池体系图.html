Executor

在体系中的位置

    抓住这些关键词

    一个任务进入 ThreadPoolExecutor 后怎么走

    顺序很重要：核心线程 → 队列 → 最大线程 → 拒绝。

    先看核心线程数

    当前工作线程少于 corePoolSize，优先创建 Worker 执行任务，即使已有空闲线程也遵循这一步。

    再尝试进入队列

    核心线程已满且线程池仍运行，调用 workQueue.offer(task) 尝试排队。

    队列成功后复查

    任务入队后还会复查线程池状态；若已关闭则移除并拒绝，无工作线程则补一个 Worker。

    队列满才扩到 maximum

    入队失败时，再尝试创建非核心 Worker，数量最多达到 maximumPoolSize。

    最后执行拒绝策略

    既不能排队也不能新增 Worker，调用 RejectedExecutionHandler；这就是系统背压边界。

    推荐学习主线

    先把“任务—执行者—结果”串起来，再进入参数与源码。

    Executor

    理解任务提交和执行方式解耦；Executor 不保证异步，也不等于线程池。

    ExecutorService + Future

    学习 submit、生命周期、Future.get/cancel，并区分 execute 与 submit 的异常。

    ThreadPoolExecutor

    掌握核心参数和任务进入顺序，不急着背“最佳线程数公式”。

    队列与拒绝策略

    比较有界、无界、直接移交队列，理解容量、延迟、吞吐与背压。

    Scheduled / ForkJoin

    遇到延时周期任务或分治计算时再学专用执行器。

    CompletableFuture / 虚拟线程

    一个负责异步编排，一个改变阻塞任务的线程成本；它们不是同一个问题。

    图以 Java 8 的稳定学习主干为中心，并标出版本变化： ExecutorService 从 JDK 19 起也是 AutoCloseable；虚拟线程每任务执行器始于 JDK 21； ForkJoinPool 在 JDK 25 增加 ScheduledExecutorService 能力。

## `sleep()`

### `sleep()` 是干嘛的？

`sleep()` 的作用是：让 **当前正在执行的线程** 暂停一段时间。注意是是 **当前执行这个代码的线程睡眠，不是某个指定线程睡眠**。它是一个静态方法



### 基本用法

```java
public class SleepDemo {
    public static void main(String[] args) {
        System.out.println("开始：" + System.currentTimeMillis());

        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        System.out.println("结束：" + System.currentTimeMillis());
    }
}
```

> **效果:**
>
> 开始：...
>
> 等 1 秒
>
> 结束：...

这里 `main` 方法是由 `main` 线程执行的，所以：`Thread.sleep(1000);`让睡眠的是：main 线程



### `sleep()` 是静态方法

`sleep()` 是 `Thread` 类的静态方法，

- 标准写法是：`Thread.sleep(1000);`
- 不推荐这样写：`t.sleep(1000);`

虽然有时候编译能过，但它会造成误解

比如：

```java
public class SleepDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            System.out.println("子线程执行");
        });

        t.sleep(1000);

        t.start();
    }
}
```



很多人会以为：`t.sleep(1000);` 是让 `t` 这个线程睡眠。但实际上不是，因为 `sleep()` 是静态方法，这里真正睡眠的是：当前执行这行代码的线程



### `sleep()` 不会释放锁

这是非常重要的点。`sleep()` 只是让线程暂时不执行，但是 **不会释放当前线程已经持有的锁**。

```java
public class SleepLockDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            synchronized (lock) {
                System.out.println("线程A拿到锁，开始睡眠");

                try {
                    Thread.sleep(3000);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }

                System.out.println("线程A睡醒，释放锁");
            }
        }, "线程A");

        Thread t2 = new Thread(() -> {
            synchronized (lock) {
                System.out.println("线程B拿到锁");
            }
        }, "线程B");

        t1.start();

        try {
            Thread.sleep(500);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        t2.start();
    }
}
```

> 大概输出：
>
> 线程A拿到锁，开始睡眠
>
> 等 3 秒
>
> 线程A睡醒，释放锁
>
> 线程B拿到锁

为什么线程 B 要等？

因为线程 A 虽然 `sleep()` 了，但是它还在 `synchronized (lock)` 里面，它没有释放 `lock` 这把锁

这个和后面的 `wait()` 释放锁不同



### `sleep()` 之后线程进入什么状态？

线程会进入 TIMED_WAITING 状态

也就是：限时等待状态

睡眠时间到了以后，线程不会立刻保证马上执行，而是重新进入可运行状态，等待 CPU 调度

所以不是说：`Thread.sleep(1000);`就一定精准地 1 秒后继续执行。

更准确地说是：至少暂停大约 1 秒，时间到了之后等待 CPU 调度。



### `sleep(0)` 是什么意思？

`Thread.sleep(0);`意思是睡眠 0 毫秒。它通常没什么实际意义。有些情况下，它可能会触发一次线程调度，但这个行为不适合作为业务逻辑依赖。



### `sleep()` 和 `join()` 的区别

`sleep()`

`Thread.sleep(1000);` 的意思是：当前线程自己休息 1 秒



`join()`

`t.join();` 意思是：**当前执行这个代码的线程** 等待 t 线程执行完

比如：

```java
Thread t = new Thread(() -> {
    try {
        Thread.sleep(1000);
    } catch (InterruptedException e) {
        e.printStackTrace();
    }

    System.out.println("子线程结束");
});

t.start();

t.join();

System.out.println("main 线程结束");
```

这里 `main` 线程会等 `t` 线程执行完之后，才打印：`main 线程结束`



### `sleep()` 被中断会怎么样？

如果一个线程 `t` 正在 `sleep()`，另一个线程调用：`t.interrupt();`

那么睡眠中的线程会被唤醒，并抛出：`InterruptedException`

```java
public class InterruptSleepDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            System.out.println("子线程开始睡眠");

            try {
                Thread.sleep(5000);
            } catch (InterruptedException e) {
                System.out.println("子线程睡眠被打断");
            }

            System.out.println("子线程继续执行");
        }, "子线程A");

        t.start();

        Thread.sleep(1000);

        t.interrupt();
    }
}
```

> 大概会输出：
>
> 子线程开始睡眠
>
> 等 1 秒
>
> 子线程睡眠被打断
>
> 子线程继续执行

注意：

`interrupt()` 不是强制杀死线程。

它只是打断阻塞状态，比如 `sleep()`、`wait()`、`join()`。

至于线程后面是否结束，要看你 catch 之后怎么写。



### `sleep()` 的异常处理

#### 基本

`Thread.sleep()` 这个方法有可能被别人打断，所以 Java 语法要求你必须提前处理这种可能性

如果直接这样写：

```java
public class SleepDemo {
    public static void main(String[] args) {
        Thread.sleep(1000);
    }
}
```

IDEA 会报错，大概意思是：Unhandled exception: java.lang.InterruptedException

意思是：你调用了一个可能抛出 `InterruptedException` 的方法，但是你没有处理它

`InterruptedException` 是一种**受检异常**，也叫 checked exception。

这种异常 Java 编译器会强制你处理



#### 为什么 `sleep()` 可能出问题？

比如一个线程正在睡觉：`Thread.sleep(5000);`意思是它准备睡 5 秒。

但是睡到一半，其他线程可能调用：`t.interrupt();`

这就相当于有人把它叫醒了。这时候 `sleep()` 就会提前结束，并抛出：`InterruptedException`

所以 `sleep()` 的真实意思更像是：

我要睡一会儿。但是如果睡觉期间有人打断我，我就抛出 `InterruptedException`。



#### 两种处理方式

##### 方式一：继续往外抛

```java
public class SleepDemo {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("开始");

        Thread.sleep(1000);

        System.out.println("结束");
    }
}
```

> 注意：throws InterruptedException
>
> 意思是：如果 `sleep()` 真的发生了 `InterruptedException`，我这个 `main` 方法不处理，继续往外抛



##### 方式二：try-catch

```java
public class SleepDemo {
    public static void main(String[] args) {
        System.out.println("开始");

        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            System.out.println("睡眠被打断了");
        }

        System.out.println("结束");
    }
}
```

> ```java
> try {
>     Thread.sleep(1000);
> }
> ```
>
> 表示：
>
> > 先尝试睡 1 秒
>
> 如果睡眠过程中被打断，就会进入：
>
> ```java
> catch (InterruptedException e) {
>     System.out.println("睡眠被打断了");
> }
> ```

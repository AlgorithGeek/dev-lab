## `notify()` / `notifyAll()`

`notify()` 和 `notifyAll()` 都是用来唤醒正在 `wait()` 的线程。

它们和 `wait()` 一样，都是 `Object` 类的方法。



### 必须配合 `synchronized` 使用

```java
synchronized (lock) {
    lock.notify();
}
```

如果当前线程没有拿到 `lock` 这把锁，就调用 `lock.notify()`，会报：`IllegalMonitorStateException`



### `notify()`

`notify()` 的作用是：随机唤醒一个正在这个锁对象上等待的线程。

注意是：一个。

比如很多线程都在：

```java
synchronized (lock) {
    lock.wait();
}
```

另一个线程调用：

```java
synchronized (lock) {
    lock.notify();
}
```

那么只有其中一个等待线程会被唤醒。

至于具体是哪一个，不要依赖这个顺序。



### `notifyAll()`

`notifyAll()` 的作用是：唤醒所有正在这个锁对象上等待的线程。

```java
synchronized (lock) {
    lock.notifyAll();
}
```

但注意：唤醒所有线程，不代表所有线程马上一起执行。

它们醒来后还要重新竞争同一把锁，谁抢到锁，谁继续从 `wait()` 后面执行。



### `notify()` 会立刻释放锁吗？

不会。

这是一个很容易误解的点。

```java
synchronized (lock) {
    lock.notifyAll();
    // 这里还在 synchronized 里面
}
```

调用 `notify()` 或 `notifyAll()` 只是发出唤醒通知。

真正释放锁，要等当前线程退出 `synchronized` 代码块。



### 更推荐 `notifyAll()` 的场景

基础学习时，可以先记住：条件复杂的时候，`notifyAll()` 通常比 `notify()` 更安全。

因为 `notify()` 只唤醒一个线程，如果刚好唤醒的是条件不满足的线程，可能导致其他真正能干活的线程还在等。

`notifyAll()` 会把所有等待线程都叫醒，让它们自己重新检查条件。

当然，配合 `notifyAll()` 时，也要用 `while` 检查条件：

```java
synchronized (lock) {
    while (!ready) {
        lock.wait();
    }
}
```



### 一句话区别

- `notify()`：叫醒一个等待线程
- `notifyAll()`：叫醒所有等待线程
- 两者都不会立刻释放锁

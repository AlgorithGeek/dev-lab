## `join()`

### 理解

`join()` 是 Java 多线程里非常重要的方法，它的核心作用是：让当前线程等待另一个线程执行完

`t.join();`代码：意思不是让 `t` 线程等待，而是让当前正在执行这行代码的线程，等待 `t` 线程执行结束。

比如这行代码写在 `main` 方法里：那就是：main 线程等待 t 线程执行完



### 千万别理解反了

很多人误会：`t.join();` 是不是让 `t` 线程暂停？不是。真正暂停的是当前正在执行这行代码的线程



### 示例

比如有两个子线程：

```java
public class JoinDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            System.out.println("线程A开始");
            try {
                Thread.sleep(2000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("线程A结束");
        }, "线程A");

        Thread t2 = new Thread(() -> {
            System.out.println("线程B开始");
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("线程B结束");
        }, "线程B");

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("main线程：两个子线程都结束了");
    }
}
```

> 先让 t1、t2 都启动
> 然后 main 等它们都结束



### `join()` 会抛异常

#### 原因

和 `sleep()` 一样，`join()` 也会抛：`InterruptedException`

为什么？因为当前线程在等待别的线程时，可能被别人 `interrupt()` 打断

比如：

- main线程正在等 t 线程结束

  另一个线程把 main线程 interrupt 了

  main线程就会从 join() 中醒来，并抛 InterruptedException

所以要处理它.



#### 方法一:直接抛出

```java
public static void main(String[] args) throws InterruptedException {
    t.join();
}
```



#### 方式二:try-catch

```java
try {
    t.join();
} catch (InterruptedException e) {
    e.printStackTrace();
}
```





### `join(long millis)`：最多等一会儿

`join()` 还有带时间的版本：`t.join(2000);`，意思是：当前线程最多等 t 线程 2 秒。

如果 2 秒内 `t` 执行完了，**当前线程** 马上继续。如果 2 秒到了，`t` 还没执行完，**当前线程** 也不等了，继续往下执行。



### `join()` 时线程是什么状态？

假设：`t.join();`这行代码由 `main` 线程执行。

那么：

- main线程进入 `WAITING` 状态
- t线程继续执行

等 `t` 执行结束后：

- main线程从 WAITING 回到 RUNNABLE
- 等待 CPU 调度后继续执行

如果是：`t.join(2000);`

那 `main` 线程进入的是：`TIMED_WAITING`

因为它最多等 2 秒



### `join()` 会不会释放锁？

`join()` 不会释放当前线程手里持有的普通业务锁

比如：

```java
synchronized (lock) {
    t.join();
}
```

如果当前线程已经拿着 `lock`，然后在里面调用 `join()`，它不会把 `lock` 释放掉

这可能会造成问题

看这个危险例子：

```java
public class JoinLockDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            synchronized (lock) {
                System.out.println("子线程拿到锁");
            }
        });

        synchronized (lock) {
            t.start();

            t.join();

            System.out.println("main结束等待");
        }
    }
}
```

这段代码可能会卡住

为什么？

```java
main线程先拿到 lock
main线程启动 t
main线程在 synchronized(lock) 里面调用 t.join()
main线程等待 t 结束

但是 t 想结束，需要进入 synchronized(lock)
可是 lock 还在 main 手里
main 又在等 t 结束

于是互相等，卡住了
```

所以记住：不要在持有锁的时候随便 join 另一个需要这把锁的线程



### `join()` 底层大概是什么？

`t.join();`: 当前线程等待 t 线程死亡。

也就是等待 `t.isAlive()` 变成 `false`。

`isAlive()` 表示线程是否还活着。t.isAlive()

如果线程已经启动但还没结束，就是 `true`

如果线程没启动，或者已经结束，就是 `false`

所以：

```java
t.join();
```

可以简单理解为：

```java
while (t.isAlive()) {
    等待;
}
```

当然真实源码比这个更细。



### `join()` 和 `start()` 的关系

一般来说，`join()` 要写在 `start()` 后面

正确：

```java
t.start();
t.join();
```

意思是：先启动 t 线程，再等待它结束。



如果你这样写：

```
t.join();
t.start();
```

那通常没意义

因为 `t` 还没启动，它还不是活跃线程，`join()` 基本会直接返回

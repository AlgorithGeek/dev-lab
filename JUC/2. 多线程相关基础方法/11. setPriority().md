## `setPriority()`

一句话：

> `setPriority()` 用来告诉线程调度器：这个线程相对更重要一点，尽量多给它一些 CPU 执行机会。

但注意，重点是：**尽量**。它不是强制命令



### 基本用法

```java
Thread t = new Thread(() -> {
    System.out.println("线程执行中");
});

t.setPriority(8);

t.start();
```

`setPriority()` 接收一个整数，范围是：`1 ~ 10`

Java 里提供了三个常量：

```java
Thread.MIN_PRIORITY   // 1
Thread.NORM_PRIORITY  // 5
Thread.MAX_PRIORITY   // 10
```

所以更推荐这样写：`t.setPriority(Thread.MAX_PRIORITY);`

而不是直接写：`t.setPriority(10);`



### 线程默认优先级是多少？

默认一般是：`Thread.NORM_PRIORITY`

也就是：`5`

可以这样看：

```java
public class PriorityDemo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            System.out.println("子线程优先级：" + Thread.currentThread().getPriority());
        });

        System.out.println("main线程优先级：" + Thread.currentThread().getPriority());

        t.start();
    }
}
```

一般输出：

```
main线程优先级：5
子线程优先级：5
```



### `getPriority()` 获取优先级

设置优先级：`t.setPriority(8);`

获取优先级：`t.getPriority();`

例子：

```java
Thread t = new Thread(() -> {
    System.out.println(Thread.currentThread().getName());
});

t.setName("线程A");
t.setPriority(Thread.MAX_PRIORITY);

System.out.println(t.getName());
System.out.println(t.getPriority());

t.start();
```

输出：

```
线程A
10
```



### 优先级越高，线程就一定先执行吗？

不一定。

这是最重要的点。

比如：

```java
Thread t1 = new Thread(() -> {
    System.out.println("低优先级线程执行");
}, "低优先级");

Thread t2 = new Thread(() -> {
    System.out.println("高优先级线程执行");
}, "高优先级");

t1.setPriority(Thread.MIN_PRIORITY); // 1
t2.setPriority(Thread.MAX_PRIORITY); // 10

t1.start();
t2.start();
```

你不能保证一定输出：

```
高优先级线程执行
低优先级线程执行
```

也可能先输出低优先级。

因为线程执行顺序最终由：

```
JVM + 操作系统线程调度器
```

共同决定。

所以线程优先级只是一个“建议”。



### 优先级真正影响的是什么？

更准确地说：

> 优先级高的线程，理论上更容易获得 CPU 时间片

但不是：

```
优先级高 = 一定先执行
优先级高 = 一定执行更多次
优先级低 = 一定后执行
```

都不是。

它只是调度参考。





### 超过范围会怎样？

线程优先级必须在：1 到 10 之间。

如果你写：`t.setPriority(11);`

或者：`t.setPriority(0);`

会报：`IllegalArgumentException`

例子：

```java
Thread t = new Thread();

t.setPriority(11); // 报错
```

因为合法范围只有：

```
Thread.MIN_PRIORITY  // 1
Thread.MAX_PRIORITY  // 10
```





### `setPriority()` 可以在 `start()` 后调用吗？

可以。

```java
Thread t = new Thread(() -> {
    while (true) {
    }
});

t.start();

t.setPriority(Thread.MAX_PRIORITY);
```

语法上没问题。

但是更推荐在 `start()` 前设置：

```java
Thread t = new Thread(() -> {
    while (true) {
    }
});

t.setPriority(Thread.MAX_PRIORITY);

t.start();
```

因为线程一旦 `start()`，它什么时候开始运行是不确定的。

你在 `start()` 后设置，可能线程已经执行了一部分了。



### 新线程会继承谁的优先级？

新创建的线程，默认会继承创建它的线程的优先级。

比如：

```java
public class PriorityDemo {
    public static void main(String[] args) {
        Thread.currentThread().setPriority(7);

        Thread t = new Thread(() -> {
            System.out.println("子线程优先级：" + Thread.currentThread().getPriority());
        });

        t.start();
    }
}
```

输出一般是：子线程优先级：7

因为 `t` 是由 `main` 线程创建的，而 `main` 的优先级被设成了 7。

不过实际开发中不建议依赖这个细节，想设置就明确写出来



### 优先级不能用来控制业务顺序

这个特别重要。

不要写这种逻辑：

```java
t1.setPriority(1);
t2.setPriority(10);

t1.start();
t2.start();

// 以为 t2 一定先执行
```

这是错误的。

如果你想让线程 B 等线程 A 执行完，用：`a.join();`



如果你想线程之间通信，用：

```
wait();
notify();
notifyAll();
```



如果想控制并发流程，后面可以学：

```
CountDownLatch
Semaphore
CyclicBarrier
Lock
Condition
```

`setPriority()` 不能用来保证顺序



### 演示：高优先级可能更容易多执行，但不稳定

你可以试一下这个：

```java
public class PriorityDemo {
    public static void main(String[] args) {
        Thread low = new Thread(() -> {
            long count = 0;
            long end = System.currentTimeMillis() + 3000;

            while (System.currentTimeMillis() < end) {
                count++;
            }

            System.out.println("低优先级 count = " + count);
        }, "低优先级");

        Thread high = new Thread(() -> {
            long count = 0;
            long end = System.currentTimeMillis() + 3000;

            while (System.currentTimeMillis() < end) {
                count++;
            }

            System.out.println("高优先级 count = " + count);
        }, "高优先级");

        low.setPriority(Thread.MIN_PRIORITY);
        high.setPriority(Thread.MAX_PRIORITY);

        low.start();
        high.start();
    }
}
```

你可能看到高优先级的 `count` 更大

但也可能不明显

原因是不同操作系统、不同 JVM、不同机器负载下，优先级效果不一样。

所以它不可靠



### 优先级和 `sleep/yield` 的关系

`setPriority()` 是告诉调度器：这个线程相对重要。

`yield()` 是当前线程主动说：我愿意让一下 CPU。

`sleep()` 是当前线程说：我要暂停一段时间。

它们不是一回事。

| 方法            | 作用                     |
| --------------- | ------------------------ |
| `setPriority()` | 设置线程调度优先级       |
| `yield()`       | 当前线程主动让出一下 CPU |
| `sleep()`       | 当前线程睡眠一段时间     |

而且这三个都不能保证业务顺序



### 实际开发中常用吗？

不太常用。

原因是：

- 平台差异大。
- 调度结果不稳定。
- 不能保证执行顺序。
- 用它控制业务逻辑很危险。

实际开发中更常见的是：

- 线程池
- 任务队列
- 锁
- 并发工具类
- 异步框架

而不是靠线程优先级调度。



### 什么时候可能会用？

一些偏底层、后台任务可能会稍微调一下，比如：

- 后台清理线程：低优先级
- 监控线程：普通优先级
- 实时性较高的任务：稍高优先级

但业务系统里一般不建议过度依赖

## `getState()`

`getState()` 的作用是：获取线程当前的状态。

```java
Thread.State state = t.getState();
```

它返回的是 `Thread.State` 枚举。



### Java 线程的几种状态

| 状态 | 含义 |
| --- | --- |
| `NEW` | 线程对象创建了，但还没有调用 `start()` |
| `RUNNABLE` | 可运行状态，可能正在运行，也可能在等 CPU 调度 |
| `BLOCKED` | 想进入 `synchronized`，但锁被别人拿着 |
| `WAITING` | 无限期等待，比如 `wait()`、`join()` |
| `TIMED_WAITING` | 限时等待，比如 `sleep()`、`wait(1000)`、`join(1000)` |
| `TERMINATED` | 线程已经执行结束 |



### 示例

```java
public class StateDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        System.out.println(t.getState());

        t.start();
        System.out.println(t.getState());

        Thread.sleep(100);
        System.out.println(t.getState());

        t.join();
        System.out.println(t.getState());
    }
}
```

可能输出：

```text
NEW
RUNNABLE
TIMED_WAITING
TERMINATED
```



### `RUNNABLE` 不等于一定正在运行

在 Java 里，`RUNNABLE` 包含两种情况：

- 正在 CPU 上运行
- 已经准备好了，正在等 CPU 分配时间片

所以看到 `RUNNABLE`，不能直接理解成“它此刻一定正在执行”。



### `getState()` 只是一个瞬间快照

线程状态变化很快。

你这一行看到它是 `RUNNABLE`，下一行它可能就变成 `TIMED_WAITING` 或 `TERMINATED` 了。

所以 `getState()` 更适合学习、调试、排查问题，不适合拿来做严格的业务流程控制。

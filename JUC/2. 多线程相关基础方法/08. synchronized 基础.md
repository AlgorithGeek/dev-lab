## `synchronized` 基础

`synchronized` 是 Java 里最基础的加锁方式。

它的作用是：同一时刻，只允许一个线程进入被保护的代码区域。

可以先把它理解成：谁先拿到锁，谁先进去；别人想进去，就要等锁释放。



### 同步代码块

最常见写法：

```java
private static final Object lock = new Object();

synchronized (lock) {
    // 需要保证线程安全的代码
}
```

这里的 `lock` 就是锁对象。

多个线程如果用的是同一把锁，那么同一时刻只能有一个线程进入这个代码块。



### 同步实例方法

```java
public synchronized void add() {
    count++;
}
```

这种写法锁住的是当前对象，也就是：`this`

等价理解：

```java
public void add() {
    synchronized (this) {
        count++;
    }
}
```



### 同步静态方法

```java
public static synchronized void test() {
    // ...
}
```

静态方法属于类，不属于某一个对象。

所以静态同步方法锁住的是：这个类的 Class 对象。

可以简单理解成：`类名.class`



### `synchronized` 能解决什么问题？

它主要解决三个问题：

1. 原子性：一段代码同一时刻只让一个线程执行
2. 可见性：一个线程改完共享变量，退出锁后，其他线程再进来能看到变化
3. 有序性：锁内部的关键操作不会被随便重排到锁外面

学基础的时候，可以先重点记住：它能保护共享数据，避免多个线程同时乱改。



### `synchronized` 是可重入锁

可重入的意思是：同一个线程已经拿到一把锁之后，可以再次进入需要同一把锁的代码。

```java
public synchronized void a() {
    b();
}

public synchronized void b() {
    System.out.println("b");
}
```

如果 `synchronized` 不可重入，那么 `a()` 里面调用 `b()` 就会把自己卡住。

但 Java 的 `synchronized` 是可重入的，所以同一个线程可以重复拿同一把锁。



### 什么时候释放锁？

正常情况下，线程执行完 `synchronized` 代码块或者同步方法，就会释放锁。

如果代码里抛异常，离开了同步代码块，也会释放锁。

但是下面这些方法不会释放 `synchronized` 的锁：

- `Thread.sleep()`
- `Thread.yield()`
- `Thread.join()`

`wait()` 比较特殊：它必须配合 `synchronized` 使用，而且调用后会释放锁。

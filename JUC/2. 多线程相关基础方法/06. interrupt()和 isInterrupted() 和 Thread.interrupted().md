## `interrupt()`

这个方法特别容易被误解。很多人一开始会以为：`t.interrupt();`. 意思是：强制停止线程. 但这其实是错的。



### `interrupt()` 到底是干嘛的？

一句话：`interrupt()` 不是杀死线程，而是给线程 **打一个“中断标记”**，可以把每个线程想象成身上有一个标记：`中断标记：false`

当你调用：`t.interrupt();` 它就变成：`中断标记：true`

但是线程到底停不停，要看线程自己的代码怎么写，比如是否有判定条件，

线程自己可以通过：`Thread.currentThread().isInterrupted()` 来判断：我是不是被别人要求中断了？





比如：

```java
public class InterruptDemo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            while (true) {
                System.out.println("子线程正在运行");
            }
        }, "子线程A");

        t.start();

        t.interrupt();
    }
}
```

你可能以为：调用 interrupt() 后，子线程就会停。

但实际上它不会停。

因为子线程代码里根本没有判断自己有没有被中断：

```java
while (true) {	//这里为 true
    System.out.println("子线程正在运行");
}
```

所以它会一直跑。



### 正确用法：线程自己检查中断标记

可以这样写：

```java
public class InterruptDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                System.out.println("子线程正在运行");
            }

            System.out.println("子线程发现自己被中断，准备结束");
        }, "子线程A");

        t.start();

        Thread.sleep(1000);

        t.interrupt();
    }
}
```

大概输出：

```java
子线程正在运行
子线程正在运行
子线程正在运行
...
子线程发现自己被中断，准备结束
```

这里关键是：

```java
Thread.currentThread().isInterrupted()
```

它会 **检查当前线程有没有被打上中断标记**

所以逻辑是：

只要没有被中断，就继续运行；

一旦发现被中断，就退出循环。



### 为什么不直接强制杀死线程？

因为强制杀死线程很危险。

假设一个线程正在执行：

```java
synchronized (lock) {
    // 修改订单状态
    // 扣库存
    // 写数据库
}
```

如果外部强行把它杀死，可能会导致：

- 订单状态改了一半
- 库存扣了一半
- 锁或资源状态混乱
- 数据不一致

所以 Java 不推荐粗暴停止线程

以前有一个方法叫：`t.stop();`

它真的比较粗暴，但已经废弃了，不推荐使用。

现在更推荐的方式是：通过 interrupt() 通知线程，让线程自己安全地结束。



### `sleep()` 中被 interrupt 会怎么样？

前面讲 `sleep()` 的时候说过：``Thread.sleep(5000);`

线程正在睡觉时，如果别人调用：`t.interrupt();`

那么 `sleep()` 会提前结束，并抛出：`InterruptedException`

看代码：

```java
public class InterruptSleepDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            System.out.println("子线程准备睡 5 秒");

            try {
                Thread.sleep(5000);
            } catch (InterruptedException e) {
                System.out.println("子线程睡眠被打断了");
            }

            System.out.println("子线程继续往下执行");
        }, "子线程A");

        t.start();

        Thread.sleep(1000);

        t.interrupt();
    }
}
```

大概输出：

- 子线程准备睡 5 秒

  子线程睡眠被打断了

  子线程继续往下执行

注意：`t.interrupt();`不是直接杀死线程。它只是把正在 `sleep()` 的线程叫醒了。醒来以后线程继续怎么走，要看你的 `catch` 里面怎么写。



### InterruptedException` 会清除中断标记

当线程正在：`Thread.sleep()`

或者: `wait()` `join()` 这些方法里面等待时，如果被 `interrupt()` 打断，会抛出：`InterruptedException`, 同时，Java 会把中断标记清掉。

意思就是：

- 原来中断标记是 true

  抛出 InterruptedException 后

  中断标记会变回 false

看这个代码：

```java
public class InterruptFlagDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try {
                Thread.sleep(5000);
            } catch (InterruptedException e) {
                System.out.println("catch 中：" + Thread.currentThread().isInterrupted());
            }
        });

        t.start();

        Thread.sleep(1000);

        t.interrupt();
    }
}
```

> 输出：catch 中：false
>
> 为什么是 `false`？
>
> 你肯定会觉得，诶明明中断了变成 `true` 了啊，这里咋是 `false`？
>
> 因为 `sleep()` 抛出 `InterruptedException` 的时候，把中断标记清除了。



### catch 中的处理方案

有两种常见处理方式

#### 方式一：直接结束线程

```java
try {
    Thread.sleep(5000);
} catch (InterruptedException e) {
    System.out.println("被中断，结束线程");
    return;
}
```

这是学习阶段最容易理解的写法。



#### 方式二：恢复中断标记

有时候当前方法不想自己处理，而是希望外层代码知道：这个线程被中断过。

那可以这样：

```java
try {
    Thread.sleep(5000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}
```

这一句：`Thread.currentThread().interrupt();`

就是重新把中断标记设回 `true`

因为前面说了，`InterruptedException` 抛出后，中断标记会被清掉

所以恢复一下，方便外层继续判断



### `interrupt()`、`isInterrupted()`、`interrupted()` 的区别

#### `interrupt()`

`t.interrupt();`

作用：给 t 线程打中断标记



#### `isInterrupted()`

`t.isInterrupted();`作用：判断 t 线程是否被中断

它不会清除中断标记。

比如：

```java
System.out.println(t.isInterrupted());
System.out.println(t.isInterrupted());
```

如果中断标记是 `true`，两次都能打印：`true`



#### `Thread.interrupted()`

`Thread.interrupted(); `作用：判断当前线程是否被中断，并且会清除中断标记

只做两件事：

- 查看当前线程的中断标记
- 如果当前标记是 true，就把它清成 false

注意它是静态方法，查的是 **当前线程**



比如：

```java
public class InterruptedDemo {
    public static void main(String[] args) {
        Thread.currentThread().interrupt();

        System.out.println(Thread.interrupted());
        System.out.println(Thread.interrupted());
    }
}
```

输出：

```
true
false
```

为什么？

第一次：

```
Thread.interrupted()
```

发现当前线程被中断了，返回 `true`，然后顺手把标记清掉。

第二次再查，就变成 `false`



**为什么设置为静态方法**

它设计成静态方法，是为了表达：这个方法永远只作用于当前线程，不需要你拿某个线程对象来调用。

Java 不鼓励外部线程去清除别的线程的中断状态。如果你真的想让某个线程清除自己的中断状态，

你要让那个线程自己的代码里调用：`Thread.interrupted()`

比如：

```java
Thread t = new Thread(() -> {
    while (true) {
        if (Thread.interrupted()) {
            System.out.println("当前线程发现中断，并清除了标记");

            // 这里可以选择退出
            break;

            // 也可以选择清除后继续干活，但一般不推荐随便忽略中断
        }
    }
});
```

外部线程通知它：`t.interrupt();` , 至于清不清除、退不退出，要由 `t` 自己决定



### `interrupt()` 能不能打断 synchronized 等锁？

这个点也很重要。

如果一个线程在这里等锁：

```java
synchronized (lock) {
    // ...
}
```

它因为拿不到锁进入 `BLOCKED` 状态

这时候你对它调用：`t.interrupt();`

一般不能让它从 `BLOCKED` 状态里立刻出来

也就是说：

- interrupt() 可以打断 sleep / wait / join 这种等待；

  但不能直接打断 synchronized 的锁竞争。



示意：

```java
public class InterruptBlockedDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            synchronized (lock) {
                while (true) {
                    // 一直占着锁
                }
            }
        }, "线程A");

        Thread t2 = new Thread(() -> {
            System.out.println("线程B准备拿锁");

            synchronized (lock) {
                System.out.println("线程B拿到锁");
            }
        }, "线程B");

        t1.start();

        Thread.sleep(500);

        t2.start();

        Thread.sleep(500);

        t2.interrupt();

        System.out.println("线程B是否被中断：" + t2.isInterrupted());
    }
}
```

线程 B 虽然被打了中断标记，但是它还是在等 `synchronized` 的锁

这个地方先有印象就行

以后学 `Lock` 的时候，会有一个方法叫：`lock.lockInterruptibly();`那个才支持“等锁时可以被中断”



### `interrupt()` 常见使用场景

#### 1. 停止一个循环任务

```java
while (!Thread.currentThread().isInterrupted()) {
    // 执行任务
}
```

外部调用：`t.interrupt();`

让它停止



#### 2. 打断 sleep / wait / join

比如线程正在睡很久：`Thread.sleep(10000);`

你不想等它自然睡醒，可以：`t.interrupt();`

让它提前醒来



#### 3. 线程池关闭任务

以后学线程池时会看到：`shutdownNow()`

它内部就会尝试中断正在执行的任务线程。

但也不是强杀。

任务代码如果不理会中断，它也可能停不下来。

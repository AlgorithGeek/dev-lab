## `setDaemon()`

它的核心作用是：

> 把一个线程设置成“守护线程”，当 JVM 中所有普通线程都结束后，JVM 不会为了守护线程继续活着。



### 什么是守护线程？

Java 线程大体可以分成两类：

| 类型                     | 含义                   |
| ------------------------ | ---------------------- |
| 用户线程 / 普通线程      | JVM 会等它执行完       |
| 守护线程 / daemon thread | JVM 不会专门等它执行完 |

普通线程可以理解成：主要工作线程

守护线程可以理解成：后台服务线程

比如垃圾回收线程 GC，就可以理解成一种典型的后台守护线程。





### 基本用法

```java
Thread t = new Thread(() -> {
    while (true) {
        System.out.println("守护线程正在运行");
    }
});

t.setDaemon(true);
t.start();

System.out.println("main 线程结束");
```

可能输出：

```
main 线程结束
```

然后程序很快就结束了。

为什么？

因为 `main` 线程是普通线程。

当 `main` 线程结束后，如果 JVM 里只剩下守护线程，那么 JVM 就会直接退出。



### `setDaemon(true)` 必须在 `start()` 前调用

正确：

```java
Thread t = new Thread(() -> {
    System.out.println("hello");
});

t.setDaemon(true);
t.start();
```

错误：

```java
Thread t = new Thread(() -> {
    System.out.println("hello");
});

t.start();
t.setDaemon(true); // 错
```

会抛异常：`IllegalThreadStateException`

原因是：

> 一个线程是不是守护线程，必须在线程启动前确定

线程启动之后，就不能再改它的 daemon 身份了



### 普通线程和守护线程的区别

先看普通线程：

```java
public class DaemonDemo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            while (true) {
                System.out.println("普通线程正在运行");

                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
        });

        t.start();

        System.out.println("main 线程结束");
    }
}
```

输出：

```
main 线程结束
普通线程正在运行
普通线程正在运行
普通线程正在运行
...
```

程序不会结束。

因为虽然 `main` 结束了，但 `t` 是普通线程，JVM 会继续等它。



再看守护线程：

```java
public class DaemonDemo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            while (true) {
                System.out.println("守护线程正在运行");

                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
        });

        t.setDaemon(true);
        t.start();

        System.out.println("main 线程结束");
    }
}
```

可能输出：

```
main 线程结束
```

或者可能来得及输出一两句：

```
守护线程正在运行
main 线程结束
```

然后程序结束。

因为只剩守护线程了，JVM 不等它。





### 守护线程不是“低级线程”

不要误会：

- 守护线程不是优先级低的线程。
- 守护线程不是性能差的线程。
- 守护线程不是一定在后台慢慢跑的线程。

它和普通线程的主要区别只有一个：JVM 退出时，会不会等待它。

普通线程还活着，JVM 不退出。

只剩守护线程，JVM 可以退出。



### 守护线程会不会突然中断？

会。

更准确地说：

> 当 JVM 发现只剩守护线程时，会直接退出，守护线程可能来不及正常收尾。

比如：

```java
Thread t = new Thread(() -> {
    try {
        while (true) {
            System.out.println("守护线程执行中");
            Thread.sleep(1000);
        }
    } finally {
        System.out.println("守护线程 finally 执行");
    }
});

t.setDaemon(true);
t.start();

System.out.println("main 结束");
```

这里的 `finally` 不一定能执行。

所以守护线程里不适合做非常关键的收尾工作，比如：

```
写重要文件
提交关键数据库事务
释放必须释放的业务资源
发送重要通知
```

因为 JVM 退出时可能不等它干完



### 守护线程的典型用途

守护线程适合做一些辅助性、后台性的工作

比如：

```
1. 后台监控
2. 定时清理缓存
3. 心跳检测
4. 日志辅助处理
5. 资源回收
```

它们的特点是：

```
主业务结束后，这些辅助线程也没必要继续让 JVM 活着。
```





### 默认是不是守护线程？

默认情况下，新线程会继承创建它的线程的 daemon 属性

通常 `main` 线程是普通线程，所以你在 `main` 里创建的新线程默认也是普通线程

比如：

```java
Thread t = new Thread(() -> {
});

System.out.println(t.isDaemon());
```

通常输出：`false`

如果想判断一个线程是不是守护线程，可以用：`t.isDaemon();`



### `setDaemon(false)` 是什么？

```java
t.setDaemon(false);
```

表示把线程设置成普通线程

不过新建线程默认通常就是普通线程，所以很多时候不需要专门写。

```java
Thread t = new Thread(() -> {
});

t.setDaemon(false); // 一般没必要
t.start();
```





### 守护线程和 `join()` 的关系

如果你主动 `join()` 一个守护线程，那当前线程还是会等它。

比如：

```java
Thread t = new Thread(() -> {
    while (true) {
    }
});

t.setDaemon(true);
t.start();

t.join(); // main 主动等它
```

这时 `main` 线程会一直等 `t`，程序也不会结束。

所以：

- daemon 的意思是 JVM 不会自动为了它继续活着。
- 但如果普通线程自己主动 join 它，那普通线程还是会等。

## `getState()`

它的作用很简单：`t.getState();` 就是获取线程 `t` 当前的状态



### `getState()` 是干嘛的？

比如：

```java
Thread t = new Thread(() -> {
    System.out.println("子线程执行");
});

System.out.println(t.getState());
```

这里线程还没启动，所以输出：`NEW`

`getState()` 返回的是一个枚举：`Thread.State`



### Java 线程一共有 6 种状态

- `NEW`
- `RUNNABLE`
- `BLOCKED`
- `WAITING`
- `TIMED_WAITING`
- `TERMINATED`

你可以先这样理解：

| 状态            | 含义                                                     |
| --------------- | -------------------------------------------------------- |
| `NEW`           | 新建状态，还没调用 `start()`                             |
| `RUNNABLE`      | 可运行状态，可能正在运行，也可能在等 CPU                 |
| `BLOCKED`       | 阻塞状态，正在等 synchronized 锁                         |
| `WAITING`       | 无限等待状态，比如 `wait()`、`join()`                    |
| `TIMED_WAITING` | 限时等待状态，比如 `sleep()`、`wait(时间)`、`join(时间)` |
| `TERMINATED`    | 线程执行结束                                             |



### `NEW`：新建状态

```java
Thread t = new Thread(() -> {
    System.out.println("hello");
});

System.out.println(t.getState());
```

输出：`NEW`

意思是：线程对象创建了，但是还没 start

只要还没调用：t.start();

它就是 `NEW`



### `RUNNABLE`：可运行状态

```java
Thread t = new Thread(() -> {
    while (true) {
    }
});

t.start();

System.out.println(t.getState());
```

大概率输出：`RUNNABLE`

`RUNNABLE` 不是简单地等于“正在运行”

它的意思更准确是：这个线程已经准备好运行了，可能正在被 CPU 执行，也可能在等待 CPU 分配时间片

比如有很多线程：

- 线程A 正在 CPU 上执行
- 线程B 已经准备好了，但暂时没抢到 CPU

它们在 Java 层面都可能叫 `RUNNABLE`

所以你要记住：`RUNNABLE` = 可运行，不一定此刻正在运行



### `BLOCKED`：等 `synchronized` 锁

`BLOCKED` 是专门指：

> 线程想进入 `synchronized`，但是锁被别人拿着，所以进不去

例子：

```java
public class StateDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            synchronized (lock) {
                while (true) {
                }
            }
        }, "线程A");

        Thread t2 = new Thread(() -> {
            synchronized (lock) {
                System.out.println("线程B拿到锁");
            }
        }, "线程B");

        t1.start();

        Thread.sleep(100);

        t2.start();

        Thread.sleep(100);

        System.out.println(t2.getState());
    }
}
```

大概率输出：`BLOCKED`

原因：

- 线程A 拿着 lock 不放
- 线程B 想进入 synchronized(lock)，但是拿不到 lock
- 所以线程B 是 `BLOCKED`

注意：`BLOCKED` 主要是等 synchronized 锁。

不是所有“卡住”都叫 `BLOCKED`



### `WAITING`：无限等待

`WAITING` 表示：线程在无限期等待别人唤醒/结束

常见情况：`lock.wait();`

或者：`t.join();`



#### 例子 1：`wait()` 导致 `WAITING`

```java
public class StateDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            synchronized (lock) {
                try {
                    lock.wait();
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
        });

        t.start();

        Thread.sleep(100);

        System.out.println(t.getState());
    }
}
```

大概率输出：`WAITING`

因为线程执行了：`lock.wait();`

它释放锁，然后无限等待别人：`lock.notify();`

或者：`lock.notifyAll();`



#### 例子 2：`join()` 导致 `WAITING`

```java
Thread t1 = new Thread(() -> {
    while (true) {
    }
});

Thread t2 = new Thread(() -> {
    try {
        t1.join();
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
});

t1.start();
t2.start();

Thread.sleep(100);

System.out.println(t2.getState());
```

`t2` 在等 `t1` 结束

如果 `t1` 一直不结束，`t2` 就可能是：`WAITING`



### `TIMED_WAITING`：限时等待

`TIMED_WAITING` 表示：线程正在等一段指定时间

最常见就是：`Thread.sleep(时间);`

例子：

```java
public class StateDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try {
                Thread.sleep(5000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        });

        t.start();

        Thread.sleep(100);

        System.out.println(t.getState());
    }
}
```

大概率输出：`TIMED_WAITING`

因为线程正在 `sleep(5000)`



常见进入 `TIMED_WAITING` 的方法：

- Thread.sleep(1000);
- lock.wait(1000);
- t.join(1000);

它们都有一个共同特点：最多等一段时间



### `TERMINATED`：结束状态

```java
public class StateDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            System.out.println("子线程执行");
        });

        t.start();

        t.join();

        System.out.println(t.getState());
    }
}
```

输出：`TERMINATED`

因为：`t.join();`

保证主线程等 `t` 执行完之后，再打印状态

线程执行完 `run()` 方法后，就进入：`TERMINATED`

注意：`TERMINATED` 的线程不能再次 `start`

如果再次：`t.start();`

会报：`IllegalThreadStateException`



### 图

```
NEW
 |
 | start()
 v
RUNNABLE
 |     |     |
 |     |     | 等 synchronized 锁
 |     |     v
 |     |   BLOCKED
 |     |
 |     | wait() / join()
 |     v
 |   WAITING
 |
 | sleep() / wait(timeout) / join(timeout)
 v
TIMED_WAITING

run() 执行完
 v
TERMINATED
```

但是注意：`BLOCKED`、`WAITING`、`TIMED_WAITING` 之后，条件满足了，通常会回到 `RUNNABLE`

比如：

- `sleep` 时间到了 -> `RUNNABLE`
- `wait` 被 `notify` 且重新抢到锁 -> `RUNNABLE`/继续执行
- `BLOCKED` 抢到锁 -> `RUNNABLE`/继续执行





### `getState()` 只是一个瞬间快照

这个很重要。

```java
System.out.println(t.getState());
```

拿到的是：调用这一瞬间的状态。

线程状态变化很快。

所以你看到的结果可能和你预想的不完全一样。

比如：

```java
t.start();
System.out.println(t.getState());
```

你可能以为一定是：`RUNNABLE`

但如果子线程很快执行完，也可能已经是：`TERMINATED`

所以如果你想观察某个状态，通常要加一点控制，比如 `sleep()`、`wait()`、死循环、锁竞争等



### `BLOCKED` 不是所有阻塞

很多人会把所有卡住都叫 blocked。

但是 Java 的 `Thread.State.BLOCKED` 特指：等 synchronized 锁。

比如：`Thread.sleep(1000);`

不是 `BLOCKED`，而是：`TIMED_WAITING`

比如：`lock.wait();`

不是 `BLOCKED`，而是：`WAITING`



### `WAITING` 和 `TIMED_WAITING` 的区别

看有没有时间限制。

```java
lock.wait();       // WAITING
lock.wait(1000);   // TIMED_WAITING

t.join();          // WAITING
t.join(1000);      // TIMED_WAITING

Thread.sleep(1000);// TIMED_WAITING
```



### `RUNNABLE` 不等于一定正在占用 CPU

Java 里的 `RUNNABLE` 包含两层意思：

```java
正在运行
准备好了，等 CPU 调度
```

所以它叫“可运行”，不是“正在运行”。

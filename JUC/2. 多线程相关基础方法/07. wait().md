## `wait()`

这个方法非常重要，而且它和前面学的 `sleep()`、`yield()` 最大的区别就是：

- wait() 会释放锁。
- sleep() 不释放锁。
- yield() 不释放锁。



### `wait()` 是干嘛的？

一句话：`wait()` 让当前线程进入等待状态，并释放当前持有的锁。它通常用在线程之间的协作场景

比如：

- 线程A：条件不满足，我先等着
- 线程B：我把条件准备好了，然后叫醒线程A

这就是 `wait()` / `notify()` 的典型用法



### `wait()` 是谁的方法？

这个地方很关键。`wait()` 不是 `Thread` 的方法，而是 `Object` 的方法。

也就是说，任何对象都有 `wait()` 方法：

```java
Object lock = new Object();

lock.wait();
```

为什么？

因为 `wait()` 和锁对象有关

比如：

```java
synchronized (lock) {
    // ...
}
```

这里线程拿的是 `lock` 这个对象上的锁。

所以等待的时候，也是围绕这个 `lock` 对象等待。



### `wait()` 必须写在 `synchronized` 里面

错误写法：

```java
Object lock = new Object();

lock.wait(); // 错误
```

会抛异常：`IllegalMonitorStateException`

正确写法：

```java
Object lock = new Object();

synchronized (lock) {
    lock.wait();
}
```

原因是：线程必须先持有 lock 这把锁，才能调用 `lock.wait()`

也就是说：

```java
synchronized (lock) {
    lock.wait();
}
```

意思是：

- 我先拿到 lock 锁
- 然后我调用 `lock.wait()`
- 调用 wait() 后，我释放 lock 锁，并进入等待状态



### `wait()` 最核心的动作

执行到：

```java
lock.wait();
```

当前线程会做几件事：

1. 释放 lock 这把锁
2. 当前线程进入 WAITING 状态（无限等待，除非被唤醒）
3. 等待其他线程调用 lock.notify() 或 lock.notifyAll()
4. 被唤醒后，重新竞争 lock 锁
5. 抢到锁之后，才能从 wait() 后面继续执行

重点是第 4 点：

> 被 `notify()` 唤醒，不代表马上继续执行。它还要重新抢锁
>
> > ✨🪐：
> >
> > `wait()` 会让当前线程释放锁并暂停；
> >
> > 之后即使被 `notify()` 唤醒，也不能立刻往下跑，必须先重新抢到同一把锁；
> >
> > 抢到锁以后，`wait()` 才返回，线程才会继续执行 `wait()` 后面的代码
> >
> > > 这里有个点，说是 `wait()` 后，这个线程进入等待/阻塞状态，被 JVM 挂起，不继续执行，也不一直占 CPU。
> > >
> > > 我最开始理解，还以为说这个拿到锁才能继续执行是因为会在执行每一行代码之前检测一下有没有锁。后来又以为是类似于死循环一样一直空转。
> > > 实际上不是，我现在理解了，这个就是给挂起了嘛，没拿到锁之前，它一直在那里挂着，除非被刻意叫醒(`notify`/`notifyAll`)啥的。
> > > 而不是说它自己有一个自动的智能逻辑，会去时时刻刻检测什么现在这个瞬时有没有锁啊之类的。这种具体和抽象的能力我还得练啊。



### 先看一个最简单例子

```java
public class WaitDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            synchronized (lock) {
                System.out.println("线程A拿到锁，准备 wait");

                try {
                    lock.wait();
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }

                System.out.println("线程A被唤醒，继续执行");
            }
        }, "线程A");

        Thread t2 = new Thread(() -> {
            synchronized (lock) {
                System.out.println("线程B拿到锁，准备 notify");

                lock.notify();

                System.out.println("线程B调用 notify 结束");
            }
        }, "线程B");

        t1.start();

        Thread.sleep(1000);

        t2.start();
    }
}
```

可能输出：

- 线程A拿到锁，准备 wait
- 线程B拿到锁，准备 notify
- 线程B调用 notify 结束
- 线程A被唤醒，继续执行



为什么线程B能拿到锁？

因为线程A执行了：`lock.wait();`

之后，线程A释放了 `lock` 锁。

所以线程B才能进入：

```java
synchronized (lock) {
    ...
}
```

如果 `wait()` 不释放锁，线程B永远进不来，也就永远没机会 `notify()`，那就死锁了

所以 `wait()` 设计成释放锁，是非常合理的



### 为什么 `wait()` 要用锁对象调用？

比如：

```java
synchronized (lock) {
    lock.wait();
}
```

这里必须是同一个 `lock`

不能这样：

```java
synchronized (lock1) {
    lock2.wait(); // 错误
}
```

因为你持有的是 `lock1` 的锁，却调用 `lock2.wait()`

这会抛：

```java
IllegalMonitorStateException
```

正确理解是：你拿了哪把锁，就只能在这把锁上 wait

也就是：

```java
synchronized (lock) {
    lock.wait();
}
```





### `notify()` 是干嘛的？

`notify()` 是唤醒一个正在这个锁对象上等待的线程

比如：

```java
synchronized (lock) {
    lock.notify();
}
```

意思是：从正在 `lock` 上 `wait` 的线程里，随机唤醒一个

注意两个点：

1. `notify()` 也必须在 `synchronized(lock)` 里面调用
2. `notify()` 唤醒的是在同一个 lock 对象上 wait 的线程



### `notifyAll()` 是干嘛的？

`notifyAll()` 是唤醒所有正在这个锁对象上等待的线程

```java
synchronized (lock) {
    lock.notifyAll();
}
```

区别：

```java
notify()    随机唤醒一个等待线程
notifyAll() 唤醒所有等待线程
```

但注意：

即使 `notifyAll()` 唤醒了所有线程，它们也不是一起执行

因为它们还要重新抢同一把锁

同一时间还是只有一个线程能拿到锁



### `wait()` 会抛 `InterruptedException`

和 `sleep()`、`join()` 一样：

```java
lock.wait();
```

也会抛：

```java
InterruptedException
```

所以要处理：

```java
try {
    lock.wait();
} catch (InterruptedException e) {
    e.printStackTrace();
}
```

如果一个线程正在 `wait()`，另一个线程调用：

```java
t.interrupt();
```

那么等待中的线程会被唤醒，并抛出 `InterruptedException`

同时，中断标记也会被清除



### `wait(long timeout)`

`wait()` 还有带时间的版本：`lock.wait(3000);`

意思是：最多等 3 秒

它有两种醒来的可能：

1. 3秒内被 notify / notifyAll 唤醒
2. 3秒到了，自己醒来

示例：

```java
synchronized (lock) {
    lock.wait(3000);
}
```

这个线程会进入：`TIMED_WAITING` （限时等待）

如果是无参的：`lock.wait();`

线程会进入：`WAITING`



### 重点：`wait()` 通常要配合 while 使用

这个非常重要

很多初学者会写：

```java
synchronized (lock) {
    if (!条件满足) {
        lock.wait();
    }

    // 执行业务
}
```

更推荐写成：

```java
synchronized (lock) {
    while (!条件满足) {
        lock.wait();
    }

    // 执行业务
}
```

为什么？

因为线程被唤醒后，不代表条件一定满足。

可能有这些情况：

1. notifyAll 唤醒了很多线程，但只有一个线程真正拿到了资源
2. 线程被误唤醒，也叫虚假唤醒
3. 被唤醒后，条件又被别的线程改变了

所以醒来后，要重新检查条件

标准写法：

```java
synchronized (lock) {
    while (!condition) {
        lock.wait();
    }

    // 条件满足后再执行
}
```





### 我的一些想法

#### 1. wait 后释放锁，别的线程进来了，那是不是多个线程一起执行同步代码块？

**不是一起执行**

更准确地说：

> 调用 `wait()` 的线程，虽然代码位置还停在 `wait()` 那一行附近，但它已经暂停执行了，并且已经释放锁了

比如线程 A：

```java
synchronized (lock) {
    System.out.println("A：准备 wait");

    lock.wait();

    System.out.println("A：wait 后继续执行");
}
```

当线程 A 执行到：`lock.wait();`

它会做两件事：

1. 释放 lock 锁
2. 自己进入 WAITING 状态，停住不执行

所以这时候线程 A 不是在继续执行同步代码块，它只是 **挂起在这个位置**

然后线程 B 才能进来：

```java
synchronized (lock) {
    System.out.println("B：拿到锁");
    lock.notify();
    System.out.println("B：notify 后继续执行");
}
```

这时候真正正在执行同步代码块的是线程 B



#### 2. 如果线程 B 执行 notify，线程 A 被唤醒了，会不会两个线程一起在代码块里执行？

不会。

因为 `notify()` 只是把线程 A 从等待状态叫醒，但线程 A **不能马上继续执行**

线程 A 被唤醒后，还要重新抢 `lock` 锁

完整流程是：

```
线程A：拿到 lock
线程A：执行 lock.wait()
线程A：释放 lock，进入 WAITING

线程B：拿到 lock
线程B：执行 lock.notify()
线程A：被唤醒，但还没有 lock，不能继续执行
线程B：继续执行 synchronized 代码块
线程B：退出 synchronized，释放 lock

线程A：重新竞争 lock
线程A：抢到 lock
线程A：从 wait() 后面继续执行
```

所以不会出现：线程A 和 线程B 同时执行 synchronized(lock) 代码块

同一时刻，真正持有 `lock` 并执行同步代码块的，仍然只有一个线程

# 02 - 模型训练与推理到底是什么？

> AI Agent 学习笔记 · LLM 基础
>
> 上一篇解决的是：
>
> **LLM 到底是个什么东西？**
>
> 这一篇要解决的是：
>
> **LLM 是怎么从“什么都不会”变成现在这个样子的？**
>
> 以及我们以后每天通过 Java 调 DeepSeek、GPT 时，到底是在：
>
> - 训练模型？
> - 修改模型？
> - 还是仅仅使用模型？
>
> 这一篇非常重要，因为下面这些词以后会反复出现：
>
> ```text
> Training
> Pre-training
> Post-training
> Fine-tuning
> Inference
> Parameters
> Prompt
> RAG
> Memory
> ```
>
> 如果这些概念最开始混在一起，后面学习 Agent 会越来越乱。

---

# 一、先看整个生命周期

先不要管具体算法。

一个大模型从诞生到被我们 Java 程序调用，可以非常粗略地分成：

```text
大量训练数据
      ↓
Pre-training
预训练
      ↓
Base Model
基础模型
      ↓
Post-training
后训练 / 对齐
      ↓
可实际交互的模型
      ↓
Deployment
模型部署
      ↓
Inference
推理
      ↓
用户得到回答
```

而我们以后：

```text
Spring Boot
    ↓
DeepSeek API
    ↓
模型
    ↓
Response
```

主要发生在最后这个阶段：

> **Inference（推理）**

而不是 Training。

这是这一篇最先要建立的认知。

---

# 二、什么叫 Training？

`Training`

中文：

> **训练**

最简单的理解：

> **通过大量数据不断调整模型内部参数，让模型逐渐学会某种能力的过程。**

上一节说过，LLM 内部存在大量：

```text
Parameters
```

也就是模型参数。

可以暂时把模型想象成：

```text
输入
 ↓
一个拥有海量参数的巨大数学函数
 ↓
输出
```

这些参数最开始并没有现在这么强的语言能力。

训练的目的就是：

```text
不断给模型数据
↓
让模型预测
↓
发现预测误差
↓
调整参数
↓
再次预测
↓
再次调整
↓
……
```

最终：

```text
参数逐渐变得合适
↓
模型能力逐渐形成
```

所以要牢记一句话：

> **训练最重要的结果之一，就是修改模型参数。**

---

# 三、模型参数到底是什么？

这里继续保持 Agent Engineer 所需要的深度。

我们暂时不研究矩阵、梯度、反向传播的数学细节。

只要知道：

模型内部拥有大量数字，例如：

```text
0.19381
-0.77213
0.00391
1.23814
-0.55192
……
```

这些数字组合起来就是模型的：

```text
Parameters
```

当然现实远比这个复杂。

但现在可以简单理解：

```text
模型结构
+
大量参数
=
当前这个模型
```

例如同一种模型架构：

```text
模型结构相同
```

但如果参数不同：

```text
Parameter Set A
Parameter Set B
```

最终表现就可能完全不同。

---

# 四、为什么参数能存下知识？

注意：

这里说的“存”不是：

```text
数据库
```

那种：

```text
北京 -> 中国首都
HashMap -> Java集合
```

一条一条保存。

不是这样。

更像：

```text
大量语言规律
大量概念关系
大量模式
```

被分布式地编码进海量参数里。

例如训练数据经常出现：

```text
Java
HashMap
Map
线程安全
ConcurrentHashMap
```

经过大量训练以后，模型内部会逐渐形成这些概念之间的关系。

所以以后问：

```text
HashMap 为什么线程不安全？
```

模型不是去执行：

```sql
SELECT answer
FROM knowledge
WHERE question = 'HashMap为什么线程不安全';
```

而是：

```text
当前输入
+
模型参数里已经学习到的规律
↓
模型计算
↓
生成回答
```

这就是：

> **参数知识**

和数据库存储的区别。

# 五、什么叫 Training Data？

就是：

> **模型训练过程中使用的数据。**

可能包含大量：

```text
自然语言文本
代码
书籍
网页
文章
文档
问答
数学内容
其他数据
```

训练数据对于模型非常重要。

因为：

```text
模型从哪里学习规律？
```

答案就是：

```text
训练数据
```

假设一个从来没学过 Java 的人。

第一次给他看：

```java
int age = 18;
```

可能完全不懂。

然后不断给他看：

```java
String name = "Tom";
```

```java
List<String> list = new ArrayList<>();
```

```java
Map<String, Object> map = new HashMap<>();
```

```java
public void save(User user) {
}
```

再配合大量：

```text
教程
项目
代码
问答
错误案例
解释
```

时间久了：

```text
Java概念
语法规律
代码结构
API关系
```

慢慢在他脑子里形成。

LLM 的训练当然跟人学习不是一回事。

但作为最初的直觉，可以理解为：

```text
海量数据
+
反复训练
↓
模型内部形成大量规律
```

# 七、什么叫 Pre-training？

这是非常重要的词。

`Pre-training`

中文：

> **预训练**

可以理解为：

> 模型第一次进行超大规模通用学习的阶段。

例如：

```text
海量文本
海量代码
海量知识
        ↓
   Pre-training
        ↓
   Base Model
```

这一阶段不是为了：

```text
专门学 Java
```

也不是：

```text
专门当客服
```

而是为了获得比较通用的：

```text
语言能力
知识表示
代码能力
推理基础
文本模式
世界知识
```

---

# 八、预训练到底在干什么？

非常经典的思路就是：

> **预测 Token。**

例如训练数据：

```text
Java 是一种非常流行的编程语言
```

训练过程中可能给模型：

```text
Java 是一种非常流行的编程
```

让它预测：

```text
语言
```

如果预测错了：

```text
程序
```

系统计算误差，然后调整参数。

下一条。

再预测。

不断：

```text
预测
↓
算误差
↓
更新参数
↓
预测
↓
算误差
↓
更新参数
```

这个过程可能重复极其庞大的次数。

最终模型逐渐学会：

```text
什么样的文本后面通常接什么
```

而为了做到这一点，又逐渐学到了：

```text
语法
语义
知识
概念关系
代码结构
推理模式
```

---

# 九、为什么叫“预训练”？

因为：

```text
Pre
```

就是：

> 预先。

意味着：

> 在模型真正被针对具体使用方式优化之前，先进行一次大规模通用训练。

所以：

```text
Pre-training
↓
得到 Base Model
```

这个模型通常已经：

```text
会语言
会续写
懂很多知识
会一定代码
```

但它未必特别适合：

```text
正常聊天
遵循用户命令
拒绝危险请求
严格输出 JSON
按要求回答问题
```

于是：

> 还需要后面的训练阶段。

---

# 十、Base Model 是什么？

经过预训练以后，可以得到：

```text
Base Model
```

中文一般叫：

> **基础模型 / 基座模型**

它已经拥有大量基础能力。

但是：

```text
会预测文本
```

和：

```text
是一个很好用的 AI 助手
```

不是完全一回事。

比如用户：

```text
请解释一下 Java ThreadLocal。
```

一个单纯 Base Model 的行为可能更像：

```text
继续预测最可能出现的文本
```

而经过后续对齐以后，模型更容易理解：

```text
用户在提问
↓
我应该解释
↓
最好结构清晰
↓
避免答非所问
```

所以现实中的聊天模型通常还有：

```text
Post-training
```

---

# 十一、什么是 Post-training？

`Post-training`

可以理解成：

> **基础预训练完成之后，为了让模型更符合实际使用需求而进行的训练。**

非常粗略地：

```text
Pre-training
↓
会很多东西

Post-training
↓
更会使用这些能力
```

例如让模型更擅长：

```text
遵循指令
回答问题
进行推理
使用工具
遵守格式
安全拒绝
进行对话
```

---

# 十二、一个非常形象的类比

假设一个人：

## Pre-training

相当于：

```text
从小学
↓
初中
↓
高中
↓
大学
↓
疯狂读各种书
```

于是：

> 知识很多。

但你突然把他拉到公司：

```text
给客户回复邮件。
```

他可能：

> “我知道很多知识，但我不知道公司要求我怎么回复。”

---

## Post-training

更像：

```text
入职培训
↓
告诉他：
如何回答客户
如何遵循要求
哪些不能做
输出格式是什么
```

于是这个人：

```text
知识
+
工作方式
```

结合起来。

再次强调：

> 这只是方便理解的类比，不是说模型真的像人一样学习。

---

# 十三、Fine-tuning 是什么？

`Fine-tuning`

中文：

> **微调**

非常重要。

简单理解：

> **在一个已经训练好的模型基础上，继续使用特定数据进行训练，从而改变模型参数，让模型更适合某类任务。**

结构：

```text
已经训练好的模型
        ↓
某一类特殊数据
        ↓
Fine-tuning
        ↓
新的模型版本
```

重点：

> **Fine-tuning 仍然属于训练。**

它和 Post-training 不是完全并列的概念：

```text
Post-training
描述预训练之后的训练阶段

Fine-tuning
描述在已有模型基础上继续训练
```

因此，Fine-tuning 可以用于 Post-training，也可以用于后续的领域适配。两者有交集，但不完全等同。

因此：

```text
Fine-tuning
↓
会修改参数
```

---

# 十四、Fine-tuning 和 Pre-training 的区别

可以先这么看：

| | Pre-training | Fine-tuning |
|---|---|---|
| 中文 | 预训练 | 微调 |
| 起点 | 模型基本从大规模训练开始 | 已经训练好的模型 |
| 数据量 | 通常极大 | 一般相对较小 |
| 目标 | 通用能力 | 专门能力或行为 |
| 参数 | 大规模训练参数 | 继续调整参数 |
| 成本 | 极高 | 一般低很多 |

例如：

```text
Pre-training
↓
学会大量自然语言和代码知识
```

然后：

```text
Fine-tuning
↓
更擅长法律文本分类
```

或者：

```text
Fine-tuning
↓
更符合某类固定输出风格
```

---

# 十五、一个 Java 类比

假设：

```text
Java工程师基础能力
```

相当于：

```text
Base Model
```

他已经会：

```text
Java
Spring Boot
MySQL
Redis
HTTP
```

然后你进入广告业务公司。

公司给你学习：

```text
Campaign
AdSet
Creative
投放规则
平台接口
内部编码规范
```

经过一段时间：

```text
普通 Java 工程师
↓
更适合广告业务的 Java 工程师
```

可以把这种感觉粗略类比成：

```text
Fine-tuning
```

但需要牢记：

模型 Fine-tuning 真正发生的是：

> **继续训练模型参数。**

# 十六、那我们学习 Agent 需要自己 Fine-tuning 吗？

前期：

> **基本不需要。**

甚至很长一段时间都不需要。

因为大量业务问题可以通过：

```text
Prompt
Tool Calling
RAG
Memory
Workflow
```

解决。

例如：

> “让模型知道公司的广告规范。”

很多初学者第一反应：

```text
拿公司文档 Fine-tuning！
```

但通常更合适的可能是：

```text
公司文档
↓
RAG
↓
检索相关内容
↓
给 LLM
```

原因后面会详细学。

现在先知道：

> **有业务知识，不代表第一反应就应该 Fine-tuning。**

---

# 十七、终于到了最重要的：Inference

`Inference`

中文：

> **推理**

这里一定注意：

AI 领域里的“推理”这个词，有时有两种语境。

---

## 第一种：Inference

指：

> **已经训练好的模型，被拿出来真正处理输入并产生输出。**

比如：

```text
你：
Java synchronized 是什么？
        ↓
模型
        ↓
输出答案
```

整个执行过程就是：

```text
Inference
```

---

## 第二种：Reasoning

更偏：

> 模型解决复杂问题时进行推理、分析、规划。

比如：

```text
分析一道复杂数学题
```

或者：

```text
分析一段复杂 Java 调用链
```

以后你会同时看到：

```text
Inference
Reasoning
```

不要把它们简单当成完全相同的东西。

这篇里说的：

> **训练 vs 推理**

这里的推理主要指：

```text
Inference
```

---

# 十八、Inference 到底发生了什么？

模型已经训练好了：

```text
Parameters
已经确定
```

然后你输入：

```text
Java HashMap 为什么线程不安全？
```

流程：

```text
用户输入
↓
Tokenization
↓
输入模型
↓
模型使用当前参数计算
↓
生成下一个 Token
↓
继续生成
↓
输出回答
```

重点：

通常在普通 Inference 过程中：

```text
模型参数不会因为这一次请求被永久修改
```

---

# 十九、这就是 Training 和 Inference 最大的区别

## Training

```text
数据
↓
模型
↓
计算误差
↓
修改参数
↓
模型发生改变
```

核心：

> **改变模型。**

---

## Inference

```text
输入
↓
已经训练好的模型
↓
计算
↓
输出
```

核心：

> **使用模型。**

---

# 二十、一句话记住

这是整篇最重要的句子之一：

> **Training 是在造/改模型，Inference 是在用模型。**

你以后忘记其它细节都没事。

这个必须记住。

---

# 二十一、拿 Java 类比一下

假设你写：

```java
public int add(int a, int b) {
    return a + b;
}
```

代码已经写完、编译部署。

用户调用：

```java
add(1, 2);
```

返回：

```text
3
```

用户调用：

```java
add(5, 8);
```

返回：

```text
13
```

这些请求：

> 并不会自动修改 `add()` 方法源码。

类似地：

```text
调用 LLM
```

一般只是：

```text
使用已有模型
```

并不会因为：

```text
你问了一句 Java 是什么
```

模型参数马上永久改变。

---

# 二十二、那我每天和 ChatGPT / DeepSeek 聊天，是不是在训练它？

这是特别容易误解的问题。

从一次实际请求本身来看：

```text
你的消息
↓
模型 Inference
↓
回答
```

这一轮本身不是：

```text
实时 Training
```

也就是说：

```text
你告诉模型：
“我最喜欢 Java。”

↓

这一轮模型回复你
```

通常不等于：

```text
模型立即把内部参数重新训练一遍
↓
全世界以后使用的模型都永久知道这个事实
```

完全不是这个机制。

---

# 二十三、但聊天数据以后会不会被拿去训练？

这是另外一个问题。

要区分：

```text
当前请求是否正在训练
```

和：

```text
服务商未来是否可能使用某些数据作为训练数据
```

这是两个不同概念。

例如：

```text
今天发生一次聊天
↓
本次是 Inference
```

未来：

```text
某些经过允许或处理的数据
↓
可能进入某个训练流程
↓
以后训练新的模型
```

这是：

```text
未来独立发生的 Training
```

而不是：

```text
你每发一句话
↓
模型立刻修改参数
```

具体某家服务商是否使用某类数据用于未来训练，需要看其具体产品政策和数据设置。

但技术概念上一定要分清：

> **使用模型，不等于实时训练模型。**

---

# 二十四、那调用 DeepSeek API 是什么？

以后我们的 Java 项目：

```text
Spring Boot
↓
DeepSeek API
↓
DeepSeek Model
↓
Response
```

这里发生的是：

> **Inference**

你的 Java：

```java
deepSeekClient.chat(...);
```

不是：

```text
训练 DeepSeek
```

而是在：

```text
请求 DeepSeek 已经训练好的模型
↓
帮你执行一次推理
```

---

# 二十五、为什么 API 调用会收费？

因为虽然不是 Training，

Inference 本身依然需要：

```text
GPU / AI 加速硬件
显存
服务器
网络
计算资源
```

尤其大型模型，每次：

```text
生成一个 Token
```

都需要进行大量计算。

所以：

```text
Inference ≠ 免费计算
```

模型提供商通常会按照：

```text
Input Token
+
Output Token
```

等方式收费。

后面 Token 那篇会详细讲。

---

# 二十六、训练为什么比推理贵得多？

从非常粗略的直觉看：

Inference：

```text
模型参数已经有了
↓
主要使用参数进行计算
↓
生成输出
```

Training：

```text
模型计算
↓
得到预测
↓
计算损失
↓
计算如何修改参数
↓
更新大量参数
```

而且：

```text
海量数据
×
大量训练步骤
×
巨大模型
```

所以大型模型训练通常消耗极其庞大的算力。

这也是为什么我们作为 Agent Engineer：

> **完全没有必要把“训练大模型”作为起步技能。**

我们的目标是：

```text
用好已经训练好的模型
```

---

# 二十七、什么是 Model Provider？

这时候可以顺便把这个概念搞清楚。

例如：

```text
DeepSeek
OpenAI
Google
Anthropic
阿里云
```

可能向开发者提供：

```text
模型
+
API
+
推理基础设施
```

于是：

```text
你的 Java 程序
        ↓
Model Provider API
        ↓
Provider 的服务器
        ↓
已经部署好的模型
        ↓
Inference
        ↓
Response
```

你不需要：

```text
自己买 GPU
自己加载几百 GB 模型
自己维护推理集群
```

这就是云端模型 API 很方便的原因。

# 二十八、什么叫 Model Deployment？

模型训练完以后：

```text
模型文件
+
参数
```

必须真正加载到计算设备上，才能提供服务。

粗略：

```text
训练好的模型
↓
部署到 GPU Server
↓
启动推理服务
↓
暴露 API
↓
应用调用
```

因此：

```text
Training
```

和：

```text
Serving / Deployment
```

和：

```text
Inference
```

也不是一个东西。

                 大量原始数据
                      │
                      ▼
                 Pre-training
                      │
                      ▼
                  Base Model
                      │
                      ▼
                 Post-training
                      │
                      ▼
              可实际使用的模型
                      │
                      ▼
                  Deployment
                      │
                      ▼
                  API Service
                      │
            ┌─────────┴─────────┐
            │                   │

            │                   │

我们的 Agent 学习：

```text
主要从这里开始
       ↓
API Service
       ↓
Inference
```

而不是：

```text
从 Pre-training 开始。
```

# 三十、现在区分第一个容易混淆的东西：Prompt

假设：

```text
模型已经训练好了
```

你输入：

```text
你是一名资深 Java 工程师，
请从并发安全角度分析下面代码。
```

这叫：

```text
Prompt
```

Prompt 会影响：

```text
这一轮模型怎么使用已有能力
```

但：

> **Prompt 一般不会修改模型参数。**

流程：

```text
Prompt
↓
成为当前输入 / Context
↓
Inference
↓
输出
```

而不是：

```text
Prompt
↓
Training
↓
修改 Parameters
```

所以：

```text
Prompt ≠ Training
```

# 三十一、一个很重要的例子

你告诉模型：

```text
从现在开始，“苹果”代表“数据库”。
```

然后问：

```text
苹果有什么作用？
```

模型可能回答：

```text
按照当前约定，苹果指数据库……
```

是不是模型学会了？

在当前对话里：

> 看起来学会了。

但是实际上很可能只是：

```text
当前 Context 中存在：
“苹果 = 数据库”
```

所以：

```text
模型利用 Context 推理
```

不是：

```text
模型参数被重新训练
```

如果下一次请求完全没有这段 Context：

```text
苹果有什么作用？
```

模型可能重新理解成：

```text
水果
```

这就是：

```text
Context 改变行为
≠
参数改变
```

# 三十二、Context 改变和 Model 改变有什么区别？

这非常非常重要。

## Context 改变

```text
模型参数
不变

输入信息
改变
```

例如：

```text
Prompt
RAG资料
聊天历史
Tool Result
```

---

## Model 改变

```text
模型参数
发生改变
```

例如：

```text
Training
Fine-tuning
```

所以：

```text
Context Engineering
```

和：

```text
Model Training
```

完全不是同一层。

# 三十三、第二个容易混淆的东西：RAG

假设公司内部有：

```text
广告投放规范.pdf
```

模型训练时根本没见过。

用户问：

```text
按照我们公司的规定，预算超过 10000 怎么处理？
```

RAG：

```text
用户问题
↓
搜索内部文档
↓
找到：
“预算超过10000必须主管审批”
↓
把文字塞进 Context
↓
LLM Inference
↓
回答
```

注意：

这里模型参数：

```text
完全没改。
```

模型只是：

```text
临时看到了相关资料。
```

因此：

> **RAG ≠ Training**

---

# 三十四、RAG 和 Fine-tuning 的本质差别

非常值得提前建立。

## RAG

```text
知识库
↓
搜索
↓
把资料放进 Context
↓
Inference
```

模型：

```text
没有被重新训练
```

---

## Fine-tuning

```text
训练数据
↓
训练过程
↓
修改模型参数
↓
产生新的模型
```

所以一个很粗但很有用的理解：

```text
RAG：
给模型“小抄”

Fine-tuning：
继续训练模型本身
```

这个类比虽然不完全严格，但初期非常好用。

---

# 三十五、第三个容易混淆的东西：Memory

比如：

```text
第一轮：
我正在分析 campaign 123。
```

第二轮：

```text
那昨天呢？
```

如果应用把之前信息保存下来：

```text
Memory / History
↓
campaign = 123
```

然后重新提供给模型：

```text
History:
用户正在分析 campaign 123

Current:
那昨天呢？
```

模型就知道：

```text
“那”指 campaign 123。
```

这里：

> 模型参数仍然没有改变。

只是：

```text
应用保存了信息
↓
下一次重新提供给模型
```

所以：

```text
Memory ≠ Training
```

---

# 三十六、Memory 和 Fine-tuning 的差别

## Memory

可能保存：

```text
用户名称
当前 Campaign
聊天历史
任务进度
偏好
```

存在哪里？

可能：

```text
Redis
MySQL
Vector DB
文件
```

然后需要时：

```text
取出来
↓
给模型
```

---

## Fine-tuning

知识/行为改变体现在：

```text
模型 Parameters
```

不是：

```text
Redis 里多一条记录。
```

这两个完全不是一个维度。

---

# 三十七、第四个容易混淆的东西：Tool Calling

假设：

```text
用户：
campaign 123 今天花了多少钱？
```

模型：

```text
我需要查询数据库。
```

然后：

```text
Tool
↓
Java
↓
MySQL
↓
5321
↓
Tool Result
↓
LLM
```

这里发生了：

```text
Inference
→ Tool
→ Inference
```

但是：

```text
没有 Training
```

Tool Calling 是：

> **模型运行时使用外部能力。**

不是：

> 重新训练模型。

---

# 三十八、现在把五个东西放在一起

这是整篇最重要的表之一。

| 技术 | 会修改模型参数吗？ | 核心作用 |
|---|---:|---|
| Training | ✅ | 训练模型能力 |
| Fine-tuning | ✅ | 针对特定任务继续训练 |
| Prompt | ❌ | 告诉模型当前怎么做 |
| RAG | ❌ | 给模型提供外部知识 |
| Memory | ❌ | 给模型提供历史/状态 |
| Tool Calling | ❌ | 让模型借助外部系统行动 |
| Inference | ❌ | 使用训练好的模型得到结果 |

一定要把这张表理解透。

# 四十、那为什么不是什么问题都靠 Fine-tuning？

因为 Fine-tuning 本身有很多成本和限制。

例如：

```text
需要准备训练数据
需要训练流程
需要验证效果
需要维护模型版本
需要重新评估
```

而且如果问题是：

```text
今天 campaign 123 消耗多少？
```

你拿 Fine-tuning 根本不合适。

因为这个数字：

```text
今天可能 5000
明天可能 7000
```

你不可能：

```text
数据库每变一次
↓
重新训练模型一次
```

正确方式当然是：

```text
Tool → 查询数据库
```

# 四十一、什么知识适合动态注入，而不是训练？

例如：

```text
实时天气
实时广告数据
今天股票价格
公司最新规范
用户当前订单
Campaign状态
```

它们具有特点：

```text
经常变化
需要精准
可能私有
```

这类信息通常应该：

```text
API
Tool
RAG
Database
```

提供。

而不是指望：

```text
模型 Parameters
```

永久保存。

# 四十二、Fine-tuning 更适合改变什么？

非常粗略地说，Fine-tuning 更经常适合：

```text
行为模式
特定任务能力
固定输出风格
领域任务适配
```

例如希望模型：

```text
长期稳定按照某类标签分类
```

或者：

```text
稳定遵循某种特殊格式和行为模式
```

才可能考虑。

但是：

> 是否真的需要 Fine-tuning，需要通过实际任务评估决定。

不是：

```text
有 AI 项目
↓
必须 Fine-tuning
```

# 四十三、还有一个重要概念：Model Version

训练以后得到的模型通常会形成某个版本。

例如可以抽象成：

```text
Model V1
```

后来：

```text
更多数据
+
新的训练
+
新的后训练
```

得到：

```text
Model V2
```

V1 和 V2：

```text
参数可能已经不同
```

所以：

```text
同一个 Prompt
```

在不同模型版本上：

```text
表现可能变化。
```

这也是为什么未来 Agent 上线以后：

> **换模型不是一个完全无风险的操作。**

以后 Evaluation 会专门解决这个问题。

# 四十四、模型为什么有大模型、小模型？

可以简单理解：

不同模型可能具有不同：

```text
参数规模
架构设计
训练数据
训练方式
推理优化
```

因此表现不同。

通常需要权衡：

```text
能力
速度
成本
延迟
```

以后选 Agent 模型的时候，并不是：

> 永远选最强模型。

例如一个任务只是：

```text
判断文本属于哪个分类
```

可能小模型：

```text
便宜
快
已经够用
```

复杂规划：

```text
可能才需要更强模型
```

这会在“模型选择”章节继续学习。

# 四十五、Inference 为什么可以并发处理很多用户？

因为：

```text
模型参数已经训练完成
```

不同用户可以：

```text
Request A
Request B
Request C
```

同时进入推理基础设施。

大概：

```text
                 已训练模型
                /    |    \
               /     |     \
          User A   User B   User C
```

它们：

```text
使用的是同一个模型能力
```

但通常拥有：

```text
各自独立的 Context
```

所以：

```text
用户A告诉模型自己的名字
```

正常情况下并不意味着：

```text
用户B的 Context 自动出现这个名字。
```

# 四十六、模型为什么不是每次调用后越来越聪明？

如果普通 API 调用自动训练参数：

```text
User A：
1 + 1 = 999
```

然后模型：

```text
马上永久学习
```

那整个模型很快就完蛋了。

恶意用户可以不断：

```text
灌输错误知识
改变行为
污染模型
```

所以：

```text
Inference
```

和：

```text
Training
```

必须在工程上严格区分。

# 四十七、Training 和普通数据库写操作也不一样

可能有人会产生这种感觉：

```text
训练模型
=
往模型里写知识
```

其实非常不准确。

数据库：

```sql
INSERT INTO knowledge
VALUES ('Java', 'programming language');
```

这是：

```text
明确的数据写入。
```

模型训练：

```text
大量样本
↓
计算误差
↓
优化模型参数
```

最终：

```text
能力和知识以分布式方式编码在参数中
```

所以模型不是：

```text
Key-Value 知识库。
```

# 四十八、训练中的 Error / Loss 是什么？

这里只建立直觉。

假设正确答案：

```text
Java 是一种编程语言。
```

模型预测：

```text
Java 是一种操作系统。
```

显然预测不好。

训练系统会计算：

```text
模型预测
vs
正确目标
```

之间的差距。

这个“差距”的数学表示通常涉及：

```text
Loss
```

中文：

> **损失**

然后：

```text
Loss
↓
计算该怎么调整参数
↓
更新 Parameters
```

随着训练：

```text
Loss 越来越合理
↓
模型预测能力逐渐改善
```

现在不用学习公式。

只需要知道：

```text
预测错
↓
计算 Loss
↓
调整参数
```

就够了。

程序保存：

```text
当前 Campaign = 123
```

下一轮继续提供。

这是：

```text
Memory
```

模型参数：

```text
没变
```

---

## Tool Calling

模型决定：

```text
queryBudget(123)
```

Java 查询：

```text
当前预算 = 8000
```

这是：

```text
Tool Calling
```

模型参数：

```text
没变
```

---

## Fine-tuning

准备大量训练样本：

```text
输入 → 正确输出
输入 → 正确输出
输入 → 正确输出
……
```

然后继续训练：

```text
模型参数更新
```

这是：

```text
Fine-tuning
```

终于：

> **模型本身发生了变化。**

# 五十七、一个核心判断方法

以后不知道某技术到底是什么时，先问：

> **它有没有修改模型参数？**

如果：

```text
修改 Parameters
```

通常更接近：

```text
Training / Fine-tuning
```

如果只是：

```text
给模型更多 Context
```

通常可能是：

```text
Prompt
RAG
Memory
Tool Result
```

这个判断法虽然不是所有情况都能完全概括，但在 Agent 入门阶段极其好用。

# 六十、整篇最核心的 12 句话

如果以后整篇忘了，只记下面这些。

### 1

> **Training 的核心是通过数据调整模型参数。**

### 2

> **Pre-training 是大规模通用训练，用于建立模型的基础能力。**

### 3

> **Fine-tuning 是基于已有模型继续训练，它仍然会修改模型参数。**

### 4

> **Inference 是使用已经训练好的模型，而不是重新训练模型。**

### 5

> **我们以后 Java 调 DeepSeek API，主要是在进行 Inference。**

### 6

> **一次普通 API 调用通常不会因为你的问题而永久修改模型参数。**

### 7

> **Prompt 改变的是当前输入 / Context，不等于 Training。**

### 8

> **RAG 给模型提供外部资料，不等于 Training。**

### 9

> **Memory 通常在应用层保存历史和状态，不等于 Training。**

### 10

> **Tool Calling 是模型运行时借助外部系统，不等于 Training。**

### 11

> **实时、私有、经常变化的数据，更适合通过 Tool、数据库或 RAG 提供，而不是训练进模型。**

### 12

> **Agent Engineer 主要研究怎么使用和组织模型能力，而不是从零训练大模型。**

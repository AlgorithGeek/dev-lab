# dev-lab

这是我的个人开发实验室。

我很喜欢“实验室”这个词。

现实中的实验室里，并不只有最终完成的成果。

那里可能有科学家随手写下的实验记录，有写了一半的草稿，有为了验证某个猜想搭起来的装置，也有失败的实验、临时的数据、已经整理好的研究成果，以及一些暂时还不知道以后有没有用的东西。

我希望这里也是这样。

这里可能会出现：

* 学习某个知识点时留下的笔记和草稿
* 为了验证一个想法写的几行代码
* 一个很小的 Demo
* 某次开发过程中踩过的坑
* 突然想明白的一件事情
* 一份后来认真整理过的笔记
* 一个值得长期维护的小项目
* 一些我觉得不错、想留下来的代码
* 还没有完成，甚至暂时不知道该放哪里的东西

有时候我会认真整理这里。

建目录、写 README、整理代码、补充说明，让某些东西变得清晰一点。

有时候我也可能只是随手创建一个文件夹，把刚刚想到的东西扔进来。

两种都可以。

因为这里首先是一个**用来学习、实验和创造的地方**，其次才是一个需要被整理得漂亮的仓库。

## 为什么会有这个仓库

以前我很喜欢认真整理编程笔记。

一个知识点，我会把概念、原理、用法、区别、示例一点点整理完整。

这种方式当然有价值。

但后来我发现，自己有时候花在“整理学习”上的时间，比真正学习、写代码和验证问题的时间还要多。

一个知识点还没有真正用过，我已经开始考虑：

它应该放在哪个目录？
文件应该叫什么名字？
这一章应该怎么组织？
是不是还缺几个知识点才能算完整？

久而久之，学习本身反而变成了维护笔记。

所以我不想让 `dev-lab` 再变成另一套需要精心维护的知识库。

我更希望自己像做实验一样学习：

遇到问题，就研究。
有个猜想，就验证。
想学一个东西，就写代码试试。
觉得值得留下，就记下来。

至于它现在是不是足够完整、漂亮、体系化，并没有那么重要。

## 关于“乱”

这个仓库以后可能不会一直很整齐。

有些目录会很规范，有 README、有说明、有完整代码。

有些目录可能只有几个文件。

有些笔记写得很好，有些可能只是几句话。

甚至可能会有一些做到一半就停下来的实验。

我觉得这没有关系。

因为这里记录的不只是最终成果，也记录过程。

如果以后某个东西变得重要，我可以再把它整理好。

如果它只是某一天为了理解一个问题留下来的几十行代码，那它完成自己的使命就已经足够了。

## 我希望这里最终留下什么

不是一个完美的知识库。

也不是一本完整的编程教材。

更不是为了向别人证明“我学过很多东西”的展示柜。

我希望很多年以后再打开这个仓库的时候，可以看到：

我曾经研究过什么，
遇到过什么问题，
写过什么东西，
做过哪些实验，
哪些地方曾经不理解，
又有哪些东西后来真的做了出来。

它可以很乱。

也可以慢慢变得越来越丰富。

这是我的实验室。

我可以在这里学习、写代码、做实验、造东西，也可以偶尔把桌子收拾干净。

---

**不必每一次探索都有成果，也不必每一样东西都有归宿。**

**先去研究，先去实践，先去创造。**

**整理可以以后再说。**
